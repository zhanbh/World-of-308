> 2026-10-19：新机制已确认，见[基线摘要](../docs/wayfinder/core-rules-v2/SUMMARY.md)和[实现差异](../docs/implementation-gaps-2026-10-19.md)。本文现有本地切片/旧契约尚未全部迁移；测试通过不等于新背包、邮箱、冷却与奖励机制已实现。

## 运行

仓库根目录执行，使用Node 24及以上（本次验证24.9.0）：

```sh
npm --prefix backend test
npm --prefix backend run check
```

测试使用Node原生TypeScript类型擦除。类型检查默认复用本机已安装Cocos Creator 3.8.8附带的TypeScript 5.8.2，不安装新依赖。其他机器可传入现有TypeScript >=5.8编译器：

```sh
npm --prefix backend run check -- /absolute/path/to/typescript/bin/tsc
```

## 已实现

- 会话打开/接管、账号和角色归属检查、按职业唯一角色、同账号唯一未完成挑战。
- 创建挑战、逐房扣体力、固定四小时刷新、同房扣费业务去重。
- 有序死亡/击杀事件批次，整批成功或整批拒绝；服务端奖励生成接口。
- 死亡10秒窗口、手动纹章复活、特殊副本累计次数；复活返回满血蓝、2秒保护和零伤害控制指令，冷却不重置。
- 死亡期间普通怪残留击杀升级仍保持dead；首领残留击杀触发通关免费复活。
- 首领与剩余小怪间接击杀共同结算，金币自动入钱包，材料/装备留地；通关装备满包待领，橙装归原角色绑定。
- 地面领取、兼容材料堆叠、满包保留、待领领取一次；场景关闭后拒绝继续拾取。
- 心跳/后台/恢复租约、独立死亡截止、通关后在线拾取不设时长上限。
- 持久化接口内的幂等结果、操作查询、账号写入栅栏、内存快照冲突重试、回滚与响应丢失模拟。此处“持久”指跟随Store提交；当前MemoryStore不具备进程外持久化。

## 当前边界

`Principal`必须由未来可信平台适配器提供；本地测试构造的身份不是微信鉴权。没有HTTP入口，不能把请求里的subject/accountId直接传成可信身份。

本切片只验证资产与挑战状态，不模拟服务端战斗。HP/MP、技能冷却和击飞的实际播放通过返回指令交给后续客户端；拾取位置验证、穿戴交换、真实属性/装备词条、绑定材料/金库、配置发布/索引/迁移和正式资产流水仍待后续实现。当前Journal是操作结果审计，不能当完整资产差额账本。

测试中的成长、掉落、副本和纹章库存均为显式fixture，集中在`test/helpers.mjs`；纹章只由测试直接准备，业务创建角色不赠送。没有正式配置默认值，也没有实现纹章获取途径。配置启动检查结构/基础数量限制，奖励交付时再校验结果；完整发布阶段的掉落上界/事务预算预检仍待实现，不能据此上线生产内容。

当前只支持未绑定材料的20个堆叠、基础装备描述及橙装交付绑定；装备穿戴时紫装绑定归下一切片。本地ID/来源键采用无歧义JSON元组，未来CloudBase适配器需映射为合规物理文档ID、加入schemaVersion/迁移，并验证SDK实际事务行为。

下一步先补完整资产差额流水、配置发布预算和只读视图/穿戴命令，再接可信身份与CloudBase适配器；Cocos接入必须另改当前“死亡即失败并清残留”的原型逻辑，不能声称在线规则已在游戏中生效。
