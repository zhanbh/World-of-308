# 本期UI状态与交付边界 v1

日期：2026-10-21。状态：将既定规则整理为状态规格，尚未实现或视觉验收；新增视觉细节仅为评审候选。依据[UI布局](ui-layout-specification-v1.md)、[城镇规则](town-interactions-proposal-v1.md)、[验收](town-interactions-acceptance-v1.md)。

## 1. 通用状态

| 状态 | 展示与允许操作 | 资产语义 |
| --- | --- | --- |
| 首次读取中 | 保留标题、关闭、占位；未取得数据的区域不显示虚构0余额或空背包 | 不能据占位发起资产操作 |
| 明确为空 | 显示空背包/无邮件/暂无待领等对应文案 | 与加载失败分开 |
| 读取失败 | 保留可靠旧数据并标“更新失败”，或显示错误和重试 | 不把失败当物品消失 |
| 提交中 | 禁用同意图重复提交及会破坏目标选择的操作；保留关闭能力 | 不提前扣金币、搬动物品或播放成功反馈 |
| 已提交、结果未知 | 显示“正在确认结果”，按原操作身份恢复；关闭后再次打开仍可恢复 | 不因暂查不到、超时或关窗创建第二笔扣费 |
| 已明确成功 | 应用服务端确认的版本、数量与费用，刷新受影响区域 | 迟到旧响应不能覆盖更高版本 |
| 已明确拒绝 | 显示原因；数据过期时刷新后重新选取 | 拒绝不消费，不自动重发用户的新意图 |

读取失败的重试与写操作未知的结果恢复必须分开；不能提供同一个“重试”按钮却隐式换请求ID。显示层可禁用对应容器操作，不等于冻结全应用导航。

## 2. 面板状态覆盖

| 面板 | 必须覆盖的状态 | 关键行为 |
| --- | --- | --- |
| 背包/换装 | 空槽、锁槽、满包、不可穿、同槽替换、卸下无空间、物品已改变 | 满包同槽替换回原格，卸下需空间；先小浮窗，再展开完整详情 |
| 一键整理 | 可整理、提交中、成功、版本冲突、结果未知 | 兼容堆叠合并，装备独立；正序空格末、倒序空格首，不改快捷模板绑定 |
| 银行 | 个人/账号页签、合法/非法绑定、选量、取消、空间不足、旧来源版本 | 两侧5列独立滚动；堆叠拖动后选量默认整叠，单件直接提交，容量不足整笔拒绝 |
| 个人库解锁 | 当前档、两币报价、选一种支付、余额不足、已解锁、满100 | 不将个人解锁传给其他角色；账号库100全开，不提供付费解锁 |
| 修理 | 穿戴/背包页签、7耐久槽、满耐久、单件、全修、余额不足、报价改变 | 一键只修穿戴；背包仅单件；无耐久部位不显示0/0或破损 |
| 强化 | 未选目标、仅武器/耳环可选、材料不足、报价变化、成功/失败/损毁、结果未知 | 隐藏概率；成功和已执行失败均消费，拒绝不消费；损毁与纪念品结果同次呈现 |
| 商店 | 选商品与数量、空间/余额不足、出售目标变化、已确认出售 | 穿戴不可直接卖；整笔购买拒绝不部分扣费；没有历史回购 |
| 邮件/待领 | 空、读取失败、部分领取、全领、过期、有附件禁删、结果未知 | 时间倒序；跳过装不下继续后项；堆叠部分领，余量保留原有效期，待领永久 |
| 副本选择 | 难度锁定、未穿武器、武器破损、0体力、允许1体力入场、提交中 | 不显示体力消耗；新挑战校验不扩到同挑战换房；创建未知不另开一局 |
| 排行 | 首次加载、空榜、缓存、刷新失败、榜外本人、翻页 | 展示数据时间，懒加载无持续轮询；本期不开放他人检视/搜索 |
| 战斗HUD | 未解锁、冷却、低蓝、耗尽、未装备饰品、破损、死亡 | 固定摇杆、普攻+四技能弧形、独立饰品、三药格；药品按类型共享10秒 |

## 3. 触摸、滚动与信息层次

背包与银行5列上下滚动已确认。拖动与滚动必须有明确手势仲裁；拖动开始后预览只表示选取，不移动权威资产。边缘拖动、跨面板、抬手取消和弹数量框必须分别验收；启动阈值与是否自动滚屏仍是视觉/手势候选，不能声称已实机通过。

小浮窗优先显示装备名称/品质/装等、关键属性及完整详情入口；完整内容必须能查看，不把省略号当完整说明。详情的比较视图保持两件身份清晰，固定宽度、并排或分步查看尚需尺寸稿；不擅自将此前未选的大面板方案重新设为默认。

品质有文字名称、耐久有当前/最大值与破损标识、属性增减有正负号，不能只靠红绿颜色。冷却显示数字或遮罩，低蓝与未解锁采用不同说明。避免持续强闪烁作为唯一提醒；具体字体、对比度、动效强度与触达需样稿/设备证据。

## 4. 本期与后续

本期包含本人信息、基础排行榜及已有背包/城镇服务；社交检视、玩家搜索、好友、私聊、城镇其他玩家展示仅留规则储备。普通手动暂停、荣誉体系及随装备更换角色外观未因UI示意进入本期开发清单，不创建其接口或数据依赖。

## 恢复体验最新确认（2026-10-21）

用户明确战斗表现不要求强一致，允许秒级回溯；短恢复先查询原请求结果，再以服务端最新确认检查点恢复，未确认移动/攻击表现允许修正。这不放松钱包、消费、发奖与原操作结果的原子性，已确认资产和收益不撤销。

持续无法恢复时显示「网络中断，请重新进入游戏」，停止继续战斗并要求重新进入；沿用既有10秒恢复窗口，不另增宽限或自动续关。未通关超时失败/关闭并保留已保存收益，已通关仅关闭拾取场景、不撤成功；新launch默认旅店，不重启续关。客户端提示不单独改服务端结果，下一请求/清理仍按原持久截止处理。

此前为减少修正提出的持久输入收据不作为本期必需方案；采用原操作结果和权威检查点恢复。秒级是体验尺度，不保证任何弱网都只退1秒；必须限制未确认预测积压，超上界先暂停等待，不允许无限本地刷怪或离线补报。具体积压上界和时间锚点待工程验证。
