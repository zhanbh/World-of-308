# 挑战金币总预算与等级缩放 v1

2026-10-19。用户确认方向：金币掉落随怪物等级动态提高，单次挑战总体维持平均水平。本稿按“同副本/难度/锁定怪物等级的完整挑战均值稳定，等级提高则均值提高”整理；具体函数、上下浮动和怪物权重尚未确认。未改代码。

## 已确认的约束

挑战进入时锁定怪物等级，挑战中角色升级不改变本次金币配置；下一次挑战再计算。读取怪物/挑战等级，不把当前角色等级、装备评分或伤害当金币加成。高等级回刷低级副本按锁定怪物等级正常产金币，不加经验衰减式金币惩罚。

前文500/3000是特定算例候选，不是所有等级同掉落的固定收入，也不是用户已确认的经济基准。金币/点券10000:1已确认，纹章售价仍待定。

## 推荐：先定完整挑战预算，再分配

服务端配置按副本、难度和锁定怪物等级读取完整挑战平均金币B，拆为击杀预算和通关预算；比例待数值联调，不因本稿自动批准70/30或其他比例。击杀预算按本次已生成遭遇的普通/精英/首领权重分到各怪物，满足全清时击杀金币和为该预算；通关部分只在合法通关时发。

怪物间允许差异：精英和首领的单只份额较高，普通怪较低；如果怪物数量变化，仍从整局预算分配，不让数量变多自动把金币总额翻倍。新增/召唤怪的奖励预算须显式配置，不能靠无限召唤增资。失败只保留已合法击杀/已获得部分，不为凑均值补发未杀怪或通关金币。

建议给整局预算一次小幅随机，例如均值的90%–110%（候选），再按权重分配为整数。先得到本次预算后，舍入尾差用固定可复现规则分配给目标奖励，避免每只各自向上取整后整体超额。不同挑战可波动；“均值稳定”不是保证每次精确同金币。

## 等级函数候选与算例

后续数值联调改见[金币曲线v2](gold-income-proposal-v2.md)：按已确认10000:1兑换及10点券纹章重算，撤回下文旧线性函数作为首选。以下仅保留历史候选，未获确认；总预算/版本/合法性方向不变。

可暂用旧候选线性尺度B(L)=B(1)×[1+0.1×(L−1)]作为首轮预算，对当前合法怪物等级逐级取表；系数0.1未获确认，后续按兑换/药品/修理/强化目标统一调整。升级副本一封顶15、二封顶30，特殊副本当前30；副本/难度各有基准，不要求所有副本同一B。

若某副本普通完整挑战B(1)=500，则L=1/5/10/15/20/30对应500/700/950/1200/1450/1950；该副本实际不开放的等级不生成配置。30级特殊B=3000仍只作另一个候选基准，不能把3000再当1级起点重复缩放。现有试算收入在配置审阅前不定稿。

例：均值3000、波动±10%，则完整挑战总金币落在2700–3300；有些怪物单只多些少些，整局受总预算约束。若基准等级提高，2700–3300这个区间也随对应B上移；不把所有等级压成同一个3000。该波动幅度只是提案。

## 事务与验收

预算版本/锁定等级/本局生成结果与挑战持久化，读取重试、重连和配置热切换不重新抽本局金币；掉落策略版本沿[动态策略方案](drop-strategy-proposal-v1.md)。每次有效击杀和通关分别幂等发放，金币入钱包及流水同事务，不能为“总预算一致”在结算时重复发放已得击杀金币。

验收：同表等级升高均值不降低；同等级同难度一局总体均值与波动符合配置；不同怪物组合不无界增加预算；整数分配守恒；重复事件不双发；失败不补未获得部分；中途升级/重连不变更本局预算；旧挑战用旧版本。当前只有规则文档，无实现/模拟通过证据。
