# 首副本时间预算敏感性 v12

2026-10-20。承接[装备分层v11](equipment-contribution-review-v11.md)，仍是设计模型，不调整正式怪物HP、攻击或经济参数。

## 目的与口径

复算：`python3 -B docs/design/analysis/encounter_time_budget_trial.py`。

当前首副本规格尚未确定房间尺寸、出生点、移速、招式范围及绕后路线，不能声称已经做了真实几何走位验证。本轮先记录互斥时间分项，检查把所有耗时差距解释成伤害不足是否合理。

每条路径逐50毫秒累计：玩家倒地占用、入房接近、攻击动作占用、对齐/躲避代理、可行动空闲、切房。每步只归一个类别，并检查分项总和等于路径总时长。动作开始后可跨入非输出窗口，残留流血继续结算；不把“技能动作占用”直接等同实际造成伤害的时间。

旧模型已有每5秒只在前65%时间允许起手的规则，这本就包含抽象走位，不能再无条件额外加35%的走位时间。新增每房0/1/2秒接近阻止新攻击，不阻止敌人进攻、已释放效果或回复；接近与已有窗口重叠只计一次。六次切房各3秒沿旧模型，不新增读条或无敌规则。没有另算清场后走到出口的距离。

情景选用起手窗口65%/50%/35%，入房接近0/1/2秒，只作敏感性输入，不是已确认的玩家操作效率或正式数值。起手窗口比例不等于最终动作占比。对齐与躲避尚无法分别计量；降低输出窗口没有同步降低敌人命中概率，因此不能据此评价走位是否“更安全”。

## 判断

1. 当前约175秒不是纯站桩时间，已含抽象走位和18秒切房；不能直接额外叠加完整移动预算而不检查重叠。
2. 只改变可输出窗口和接近时间，保底武器结果就可跨过4分钟附近。说明目标对操作/几何假设敏感，不证明35%或50%才是真实值，更不能为凑240秒反向指定玩家发呆。
3. 10级全蓝即使使用最保守的本轮窗口仍约166秒，装备成长带来的刷本提速应保留。“普通首次约4分钟”不能扩大成所有等级/所有配装固定4分钟；首次挑战的升级回满/技能解锁尚未模拟。
4. 现阶段不提高怪物HP、不削弱武器或防具、不按这些耗时发布每小时金币收益。先给场景与招式建立统一坐标单位，用出生点距离/移速求接近时间，用范围、锁向和退出距离求躲避，再取代抽象窗口。

## 后续需要的证据

- 玩家、怪物移动和碰撞范围统一源像素/世界单位；相机显示比例不能混入距离公式。
- 精英横扫、Boss重槌/践踏/冲撞/吼叫的起手、结算、收招及霸体节点；当前时间代理不完整。
- 基础玩家策略：接近、对齐、攻击、离开范围、绕后、回到攻击距离，不能通过出招随机命中率代替真实路线验证。
- 房内全怪同时出现，进攻协调与走位空间需联动；不能靠接近阶段不让怪物攻击制造安全通关。

本轮无新增玩法取舍需要用户确认。继续先补这些候选场景参数和反例，不把有限模型结论升级成正式配置。

## 验证与局限

1200条路径时间守恒；显式65%/0秒与默认模型逐字段一致；28怪与固定种子回放通过。v10和v11脚本在加计时字段后回归通过。沿用固定护甲、期望暴击、库存和首次致死截止等既有局限；尚无坐标AI、经验成长、真实输入或真机证据。
