# 位移技能地图边界交接 v1

2026-10-20。玩家不得因朝边缘释放大崩而出地图，这是用户已确认规则。本轮补设计约束与离线参考，遵循既有设计审阅门禁，未修改客户端业务代码。

## 已确认约束

所有位移技能都受地图可通行边界限制，不只大崩，也覆盖崩山击和后续职业技能。整条移动轨迹合法，不能只验证最终落点；跳跃画面升高不允许越出地面地图。短距离、长距离、急速改变完成时间、边缘起手或更新步长较大均需满足。

可通行边界采用地图实际玩法碰撞范围，不是屏幕可见范围或相机边框。碰撞范围、足迹大小、场景单位需统一；当前原型矩形和8像素足迹只是测试输入。

## 推荐实现方案（尚未业务实现）

1. 每次推进位移，先计算本帧期望位移，再沿路径检测与地图边缘/实体障碍的首次接触，只有合法部分写入角色地面位置。避免只判断终点造成薄墙穿透。
2. 碰撞考虑角色地面足迹；地图边缘留出碰撞体空间，不以立绘飘带、武器特效或跳跃高度作为角色可通行边界。
3. 参考方案先在接触处截停本帧位移；墙面滑动、复杂地形和障碍角落由正式移动模块统一处理，不在每个技能各写一套。参考实现对矩形障碍使用保守方形足迹膨胀，尚不等于最终圆形/导航网格碰撞。
4. 被截掉的位移当帧丢弃，不累计为后续突然补偿；下一帧按本帧轨迹增量再检查，不能离开墙面后把余量一次弹出去。贴墙后反方向仍应正常移动。
5. 建议碰边仅截位移，动作、消耗与伤害节点继续原时间轴，并以实际合法位置判范围；不自动反弹、传送、重置技能、退还资源或增加无敌。这是待工程审阅的方案，不把用户“不得出地图”扩展成已确认所有碰墙玩法。
6. 客户端与未来权威模拟共用地图碰撞数据/配置版本和边界算法口径。客户端表现不能单独允许越界，再靠回拉掩盖。

## 参考验证

运行 `python3 -B docs/design/analysis/displacement_boundary_trial.py`：崩山34、大崩64/100源像素，两侧边缘与角落/空地、q1/2共30组，60/120Hz轨迹终点一致；另检查上下斜向大步长、薄墙穿透、贴墙继续向外与反向离墙。参考算法只允许合法移动，越界部分被截断。

确认结果：边缘/角落不能越出足迹边界；空地100像素位移仍完整100像素；跨薄墙的大步长在首次接触处停下；已贴墙时能反向离开，不积蓄额外位移。此为参考模型检查，不是Cocos或服务端已修复。

现有Prototype/CombatModel会对锚点矩形夹紧，v15几何模型考虑候选足迹；正式迁移要统一，不能将当前硬编码[-218,218]等数值复制成所有地图的边界。尚无复杂地图、动态障碍、角色重叠、网络纠偏或真机验证。
