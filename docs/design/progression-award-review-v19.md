2026-10-20。沿[原经验候选表](combat-numeric-proposal-v1.md)，把整数奖励、等级跨越和已持有装备分开。运行 `python3 -B docs/design/analysis/progression_award_trial.py`。仅离线生命周期，不是完整成长战斗仿真。

## 已确认规则的参考处理

- 活着升级恢复新上限满血满蓝；死亡状态升级不会自动复活，既有手动/首Boss残留击杀复活规则继续有效。
- 每5级优秀武器发邮箱，同一等级奖励不能重复发放；不因为等级到了就替换玩家当前武器。领取和穿戴是独立步骤。
- 达30级后不再累计经验，溢出不折现；奖励重试不会重复升级或再次发邮件。本脚本去重仅顺序内存参考，不替代实际原子资产事务。

原配装函数默认随角色等级推定检查点装备，是旧静态算例；本轮增加显式item_level与starter_quality，可固定持有白武器装等10，角色升级只增长人物属性/技能，不凭空获得优秀品质/下一档武器攻击。默认调用继续保留历史算例以便回归，不能误用旧默认函数作为动态装备系统。

## 经验候选与紫名预算

每局经验固定为4×[100+20×(入口锁定怪物等级−1)]，沿旧4分钟基准反推候选，但实际拖延挑战不增加预算。普通25只、紫名1只、精英1只、Boss1只；普通单位1，紫名2，精英4，Boss约8，权重共39。

怪物总经验取预算70%向下取整，普通单位经验取整；紫名严格为对应普通2倍。整数尾差归Boss份额，通关取得剩余30%左右，总和精确守恒。本分配权重、衰减函数和预算均是候选，不是最终配置。

原候选等级差衰减max(0.1,1−0.1×等级差)另列对照，按每笔奖励时玩家等级计算，未确认正式采用。入口怪物等级固定，中途玩家升级不改变该局怪物；15级后的第二升级副本只按已有区间选用匹配等级，此脚本不生成其完整地图。

## 1–30级预算检查

| 每局输入时长 | 不衰减：局数 / 时间 | 候选等级差衰减：局数 / 时间 |
| --- | --- | --- |
| 3分钟 | 59局 / 2.95小时 | 60局 / 3.00小时 |
| 4分钟 | 59局 / 3.93小时 | 60局 / 4.00小时 |
| 5分钟 | 59局 / 4.92小时 | 60局 / 5.00小时 |

这些时间是“固定局数×输入分钟”，不是战斗模型算出的实际成长耗时。没有城镇操作、失败、体力等待、装备掉落或职业差异，不能据此宣布3–5小时满级已验证。局末领取最优保底与不领取在这份固定时长模型里耗时相同，刻意不伪造装备对实际战斗的反馈。
