## 1. 当前代码与迁移起点

核对范围：后端领域模型/规则、GameService、Store端口、内存适配器说明及客户端模型入口；并非逐行代码审计。

| 现有入口 | 可复用基础 | 必须迁移或补齐 |
| --- | --- | --- |
| `backend/src/domain/model.ts` | 账号/会话、角色、挑战/房间、奖励来源 | schema版本、三类容器、绑定堆叠、耐久、邮箱、体力快照及完整配置引用 |
| `backend/src/application/game-service.ts` | 命令协调、归属检查、请求结果、挑战/领取 | 当前创建10格、逐房要求余额足额、旧复活冷却；正式初始化、读模型及资产服务缺失 |
| `backend/src/domain/rules.ts` | 时间窗、成长、基础堆叠与配置校验 | 基于角色余额刷新的体力逻辑不符合挑战快照；基础堆叠不含完整绑定来源 |
| `backend/src/ports/store.ts`、内存适配器 | 事务抽象、提交未知/失败场景 | 内存不能进程外持久；真实适配器的并发、索引、权限和预算需验证 |
| `shared/src/protocol/types.ts` | 现有命令与结果契约 | 状态查询、版本、资产指令、UI服务、场景/快照边界 |

旧49项测试是历史实现证据，本轮未重跑，数量不作为未来验收门槛。原型、美术稿、本地内存事务通过都不能证明真实在线闭环完成。

## 2. 范围、配置与交付边界

最终MVP仍有战士和猎人、三个副本与四档/两档难度。首次端到端验收可选战士和首副本普通7房，作为较小的验证路径，不删减MVP或强制1级角色拥有高阶技能。猎人动作精修、拍卖交易、充值和活动沿现有后置边界。

最低测试配置需显式包含：schema/协议/内容版本、职业与技能模板、13槽装备及绑定、药品/饰品、三类容器、商店及服务价格、副本/怪物/行为/抗性、经验/金币及掉落策略、体力时间窗。未定价格和伤害只能放入标记为测试用途的配置，不得作为生产默认；缺少必要配置应明确拒绝，不静默编造数值。

服务端生成并持久化奖励计划、紫名安排与随机结果；响应丢失或重试不重抽。动态掉落策略应独立实现，测试缺件优先不扩大到怪物全部掉落、不自动变成正式保底；挑战是否固定策略版本按发布方案明确，不将候选实现选择冒充产品决定。

### S01：基线、版本与配置

交付：明确请求/结果、读模型、schemaVersion及配置引用；将已确认规则与测试数值分开；旧数据字段盘点和升级路径。范围包含个人/账号金库区别、服务地点、体力快照和组合怪物，不沿旧摘要覆盖最新决定。

验收：无效职业/装备槽、缺少价格、非法绑定或技能变体引用等被拒绝；旧版本可明确升级或安全拒绝。每项迁移有前后示例，不靠删存档“迁移成功”。

### S02：资产与容器基础

交付：背包、角色个人金库、账号金库独立所有权与版本；装备唯一位置、堆叠模板/绑定/归属；资产差额流水与原请求查询。当前Journal不能替代完整账本；随机生成不能放在可能重复执行的事务回调中重抽。

验收：同物品不能同时在两容器；负数量、越权、旧会话、同操作ID不同请求体均拒绝；提交前失败无资产变化，提交成功响应丢失可查原结果；并发转移不复制或丢物。覆盖UI03–UI05/UI14。

### S03：初始化与领取

交付：每职业唯一角色、20格背包、角色绑定初始白武器；一次新手邮件8血药/8蓝药/10纹章，不赠初始货币；等级武器邮件来源防重；邮件30天与永久待领独立生命周期、倒序列表和领取接口。排行榜/个人信息只读字段不得暴露私有钱包和金库。

验收：重试创角不多发；升级跨多个节点每节点只发一次；邮件部分领取保留未领附件、过期按规则删除、待领不过期；绑定不因领取改变，未领物不计快捷位库存。覆盖UI11–UI13。

### S04：挑战状态、体力与场景

交付：至少1点开本，普通1/特殊3逐房扣本局快照至0，0仍能打完；固定刷新不注入本局，短暂重连保持快照，回城加载最新窗口。每房实际/零扣费持久去重。上线旅店、在线回城对应副本门口与短暂重连继续挑战分开建模。

迁移死亡10秒、恢复10秒、特殊副本复活各3次、残留首领击杀免费复活；复活清职业CD，药品/饰品不清，回城全部清，短暂重连不清；满级经验及难度解锁沿现有规格。

验收：1点开特殊本、到0跨刷新、同房重试、重登/接管、死亡与恢复截止独立；一旦死亡/通关终态成立不能被旧事件覆盖。提交快照升级前须明确老挑战的可恢复或终止策略，不私自续关。覆盖LOC01–LOC09。

### S05：装备、耐久与修理

交付：13槽校验、满包原格替换、卸下需空格、紫装穿戴绑定、属性聚合/套装计件、武器和耳环强化属性引用；7槽耐久、清房−1/死亡额外−5并独立去重；林纳克斯单件及当前穿戴全修。

验收：无武器/0耐久武器禁入；非武器归零可继续但失去属性/套装计件；武器归零暂停提示自行退出；末房首领有效击杀后磨损归零仍通关发奖。费用由缺失耐久与装等品质价计算，不随强化/词条加价，金币不足全修整批拒绝。直接修背包装备范围尚待定，不自行加限制。覆盖UI01/UI08。

### S06：战斗与怪物配置

交付：跨普攻/技能直接伤害累计倒地、起身重置、流血不计；AP及属性/急速/技能成长采用已确认结构，流血释放时锁预算、逐跳独立暴击、急速压缩间隔/持续时间且不增基础总伤害、重复施放保留未结算预算。具体参数等待用户伤害试算。

按D04接模板/类型/身份/技能/行为/抗性组合；四类默认、人形牛头精英与Boss特殊设定、技能动作节点、中断与脱手效果、起手计冷却。首副本全房同时出现、紫名额外1只R1–R6、全灭开门、群怪协调和站位；Boss50%切阶段保留当前招式及CD，扇形锁向吼叫和倒地后持续推离。

验收：同技能跨模板、相同模板变Boss不隐式免控；免流血不免直接伤害；施招霸体仍受伤/流血，收招恢复；吼叫单次最多倒地一次、倒地后范围内仍持续受伤/击退；中断不退CD，重连不重抽紫名。未定数值不妨碍独立规则fixture验证，但不能据此宣称已平衡。

### S07：银行、商店与付费解锁

交付：个人20→100、4次各20，可选金币/点券；账号100全开；角色绑定物仅能进本角色个人金库。金币背包扩容、商人买卖及已定虚拟金币/点券兑换边界；不是接入真实充值。所有计价服务端权威。

验收：所选数量容量不足整次不转移；个人解锁不共享；同档并发两币只能成功一次，不双扣；商人不收穿戴物、无回购；换页不把请求误写另一类金库。UI02–UI07/UI10/UI14。

### S08：强化、策略与评分

交付：武器/耳环至+20，按目标等级执行既定保级/降级/损毁，纪念品统一角色绑定、20堆叠、一次一组，满包溢出邮件；隐藏成功率。按等级总金币预算分配及版本化掉落策略，随机怪物掉落与测试通关缺件优先分开。

持有检测已确认包含当前角色穿戴、背包、个人金库、账号金库、有效邮件及永久待领；仅计当前角色可用的对应套装/档位/部位，排除其他角色绑定物，不扫描其他角色个人库。评分按当前穿戴可重建，提供总榜/职业榜，旧投影不能覆盖新版本。

验收：同强化请求不重抽、不多扣，拒绝不消耗；损毁物品不残留穿戴/容器引用；策略切换不重生成已定奖励；金币整数分配守恒；同分以达到当前分数时间排序，卸装/强化/损毁更新投影。UI09及相应排行场景。

### S09：Cocos功能连接

交付：可信会话调用边界、服务面板状态与最新资产读取、角色/城镇/副本场景转换；UI入口和左右布局按D05清单，地图入口范围触发与离开再触发；角色隔离旅店、银行双页签、邮箱/待领提醒。服务面板停止移动，关闭不取消在途资产请求。

验收：双触/拖动误触、关闭时已提交、超时后再打开、旧会话接管都有可核对结果；区分待确认、拒绝、成功，不把未知当失败重发。模拟适配与真实线上状态显式区分；保存动作原型，不直接以庞大Prototype脚本承担资产权威。

### S10：可信身份与持久适配

先产出平台选择、权限、集合/索引、事务预算与本地契约适配方案；实际资源需明确目标环境后再操作。本轮不创建资源，不配置密钥。

验收：Principal只能由可信微信适配获得，请求体账号ID不可冒充；会话接管撤销旧写权限。真实事务并发/未知提交结果/超限行为有证据；关闭进程再登录资产仍在。MemoryStore测试不能替代这些结论。

### S11：真实闭环与交付门槛

战士创建→旅店→走到入口→普通7房→死亡复活或通关→满包待领→回城对应门口→邮箱领取/换装→银行存取→修理/买卖→重进旅店并读取资产。补测1点体力跨刷新、强化损毁、响应丢失、旧会话和隔离容器，不能只跑顺畅路径。

证据分为领域/事务自动化、客户端模型、平台持久适配、手机人工验收四层；逐条记录配置版本、环境、预期/实际和未通过项。Note20 Ultra微信横屏触达、信息密度、持续运行帧率与包体须独立验证，浏览器/桌面运行不代替手机结论。

## 4. 迁移与回退要求

1. 修改模型前盘点旧schema、容器和活跃挑战；明确哪些为测试数据，是否清档由用户决定，不能默认删库。
2. 迁移需保留装备实例、绑定、领取来源、原请求结果和资产流水；10格背包升级20格不复制物品或反复赠初始化奖励。
3. 体力旧挑战字段、角色刷新窗口和快照需有版本化转换；无法证明可安全恢复时提出明确处理方案，不暗中把旧挑战当新挑战重扣。
4. 协议/配置不兼容时拒绝并给出可恢复反馈；回退不能只回代码后遗弃已写新结构，需兼容读取或停止写入后修复。
5. 未定义的新资产变更不通过客户端整包存档覆盖服务端解决。

## 5. UI并行设计交接

D05已确认交互足以开始独立UI设计，不要求S01–S11实现完。先统一480×270源像素/960×540显示口径、字体、色板、间距、触控尺寸和通用状态，再按背包/属性、银行/服务、城镇/入口/邮箱分组。

每组输入为D05方案与验收清单；输出为界面稿、组件/资源规格、状态图及规则引用。覆盖空、满、锁定、金币不足、处理中、结果未知、成功/失败；未定价格用占位，不自定规则。共享两栏方向以各功能已确认布局为准，不能为统一视觉擅自颠倒。新会话仅在用户明确要求后创建，本轮未创建或发送跨会话消息。
