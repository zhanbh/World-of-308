## 验收准则（AC19-1 ～ AC19-8）

- **AC19-1：特殊副本与套装资格过滤**
  - 套装装备掉落与缺件策略严格限定于 30 级特殊副本（`special dungeon`，`monsterLevel === 30` 且 `c.level === 30`）；
  - 普通剧情副本或非 30 级特殊副本严禁通过策略产出套装；普通副本尝试产出套装直接拒绝（`CONFIG_NOT_READY`）；
  - 非套装装备、普通白/绿/紫装不进入套装策略与缺件过滤；掉落前必须经过来源、装等、品质（橙色/套装）、职业资格校验。

- **AC19-2：策略解耦与动态 Profile 调度**
  - 掉落策略算法与配置 Profile 严格解耦；实现服务端策略注册表：
    - `weighted-random`：标准权重随机抽取，允许抽取到重复部位；
    - `missing-slot-first`：缺件优先策略（测试期特殊副本通关 100% 优先补齐缺失部位，全齐触发回退）；
    - `weighted-missing-first`：缺件加权策略（正式服候选，通关抽到套装时，对缺失部位按配置权重进行偏向加权）；
  - 动态策略配置结构包含：`profileId`、不可变 `version`、`strategyId`、`candidates`、`fallbackStrategy`、`holdingsDomain`；
  - 挑战创建时固定策略 Profile 引用（`dropProfileRef`），挑战进行中不受外部配置更新影响，下一次新挑战才采用新版本。

- **AC19-3：全口径持有汇总覆盖**
  - 持有判定范围必须完整覆盖以下六大存储源：
    1. 当前角色 13 槽穿戴装备（`equipped`）；
    2. 当前角色背包（`backpack`）；
    3. 当前角色个人金库（`personal vault`）；
    4. 账号公共金库（`account vault`，仅限符合当前角色职业可用性的合法共享物）；
    5. 当前角色未过期的有效邮件（`mailLatestExpiryAt > now`）；
    6. 当前角色永久待领奖励（`pendingGrantIds`）；
  - 地面未拾取掉落不计入持有；0 耐久装备仍视为已持有；耐久磨损、修理、未损毁强化不改变持有计数。

- **AC19-4：严格角色私域隔离与账号金库共享**
  - 同一账号下的多个角色严格隔离；角色 A 的背包、穿戴、个人金库、待领与邮件，即便未绑定或账号绑定，也**绝对不共享**给角色 B，角色 B 判定缺件时严格排除；
  - 只有真正存入公共账号金库中的共享装备，才计入账号 scope 并在当前角色查询缺件时生效；
  - 绑定类型仅决定能否存入账号金库，不扩大角色私域物品的共享范围。

- **AC19-5：邮件时效性判定与最大期限维护**
  - 汇总中邮件时效性通过 `mailLatestExpiryAt` 保存最晚到期时刻，`now >= mailLatestExpiryAt` 时无需后台定时清理任务即可判定邮件贡献过期并自动恢复为缺件；
  - 移除最大期限贡献时，通过事务外取次大候选并在写栅栏重验，原子更新新最大期限；
  - 邮件附件领取时转化为 permanentCount 并扣减邮件贡献，总持有量不重复增加。

- **AC19-6：固定随机样本、OCC 重映射与提交不可变**
  - 基础随机样本由 `sourceKey` 与配置哈希确定性生成；
  - 并发 OCC 冲突重试时，若同笔持有版本变化，未提交候选根据最新持有重映射，但基础随机样本绝对不重新抽样（防止样本漂移）；
  - 一旦首次事务提交成功，生成的装备实例、pending grant 与原回执 `clearReceipt` 永久不可变，丢包与重复重试幂等返回原回执。

- **AC19-7：全齐安全回退与完整性保护**
  - 当当前角色已集齐该套装全部 11 个部位时，策略必须平滑触发 `fallbackStrategy`（如 `weighted-random`），随机发放一件合法套装部位，严禁整笔报错、卡死或拒发；
  - 汇总损坏（缺摘要、负数、domainRef 不匹配）时整笔原子拒绝，严禁把完整性损坏当成缺件补发装备。

- **AC19-8：生命周期联动与客户端收集展示**
  - 出售或强化损毁最后一件该部位装备，同笔原子更新汇总，对应部位即时恢复缺件状态；
  - 客户端提供套装收集度查询与协调器展示（如 `X/11` 进度、各部位高亮/灰显、通关结算获得套装补全反馈）；
  - 网络异常进入未知状态时支持幂等恢复。

## 配置边界与待实施核对

1. **测试 Profile 与正式 Profile 严格隔离**：
   - 测试 Profile（`test-terminal-special-v1`）：特殊副本通关 100% 触发套装掉落且启用 `missing-slot-first`；
   - 正式 Profile 候选：套装掉落概率、随机/加权/保底策略待策划签署，禁止直接将测试 100% 缺件优先配置作为正式配置；
2. **套装定义与部位映射**：
   - 30 级套装由 11 个部位构成（武器、耳环、戒指、手镯、项链、辅助装备、魔法石、肩甲、上衣、裤子、腰带、鞋子中的 11 个对应套装部位）；
   - `collectionKey` 严格编码为 `(setId, itemLevel, slotId, classId)`，每份持有汇总最多 64 个键，编码尺寸不超过 16KiB；
3. **环境与数据隔离**：
   - 所有测试使用显式 `isolated-local-assets-only` 授权，不操作云端数据库，不调用外部网络。

## 测试边界及范围

- **纯规则与策略层**：策略算法独立单元测试、多 Profile 调度、权重计算与全齐回退逻辑；
- **领域服务与事务层**：
  - 双角色三容器（穿戴/背包/个人库/账号库）多源持有判定与严格角色隔离；
  - 邮件有效期边界（未过期持有、过期自动恢复缺件）；
  - 装备出售/强化损毁后缺件即时恢复；
  - 并发 OCC 重试时固定样本重映射；
  - 11 实体原子故障逐写点回滚；
- **客户端与表现层**：套装收集进度与部位高亮模型、通关结算反馈、未知丢包恢复；
- **全链路联合验收**：全 11 部位逐一补全至全齐大闭环、终局物理预算实测（R44 / W33）、Standards 与 Spec 两轴独立评审。
