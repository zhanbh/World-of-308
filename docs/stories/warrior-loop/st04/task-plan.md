## 建议任务

### ST04-01：打开背包并完成权威正倒序排序

**Blocked by：** 外部E01最小公开命令/结果/检查合同、ST02归属与合法背包能力；无本故事内阻塞项。

**交付：** 玩家打开自己的背包，执行排序并看到权威结果；通过窄协议接入应用服务、容器模型与客户端状态，不仅新增纯排序函数。该任务只验证无可合并堆的排序路径；完整“一键整理”尚未交付，不把它当最终整理入口开放。

- 正序装备→消耗品→材料，装备部位固定顺序/品质降序/装等降序，同键稳定；模板排序稳定；正序空格末，倒序按已确认规则反转排列、空格首。固定部位枚举以权威配置为准，不自行发明优先级。
- 实际容量20～100格，锁格不可写；只整理当前角色背包，不改金库、装备实例属性/location/version或快捷绑定。
- 缺失/畸形sortHeader明确拒绝或进入受控重建，不默认空值排序，不在此新增全历史扫描。
- 归属/会话/版本校验、同operation同参重放/异参拒绝、O/J/A和容器原子提交；纯排序保留quantity与traceRef，仅记录有界排列。
- 客户端具有加载、明确空、失败、提交中、结果未知状态；未知沿原operation恢复，迟到旧版本不覆盖新背包。
- unit验证排序边界；内存事务integration验证并发、逐写故障和提交丢响应；contract验证公开DTO/授权/拒绝；提供客户端状态或命令演示。真实平台待验单列。

### ST04-02：一键整理合并兼容堆并保留数量谱系

**Blocked by：** ST04-01；不额外依赖邮件/银行功能上线，合法来源可用已提交的最小审计夹具提供。

**交付：** 将排序路径扩成完整“一键整理”：一次提交先合堆后排序，客户端展示最终背包和实际合并摘要。

- 仅同模板、同绑定归属及其他堆叠条件兼容项合并，每堆1～20；装备不合并；不改数量/绑定/来源资格，不跨角色或跨库。
- 合并受影响的输入和输出（包括余量）写一个有界J，输出traceRef确定且可追溯；纯位置变化不增长来源链，不递归读取祖先流水。
- 合并与排序一次原子提交；同ID重试不再次合并/发物，明确拒绝不造资产流水；J已存在O缺失不得二次执行。
- 满100格、多绑定、多来源、20/21/40数量边界与重复整理守恒；银行不变、装备不被逐件改写；检测容器/流水/原结果实际UTF-8编码预算（64/128/16KiB）。预算不满足时不能截断或部分整理。
- 客户端完整整理入口在本任务验收后启用；显示提交中/未知/失败并按版本合并查询结果，不把原请求摘要当完整背包快照。
- unit、contract、内存integration覆盖每参与写点失败、冲突重试两种顺序及提交丢响应；保留有效旧事务不变量，不靠删测试造绿灯。

### ST04-03：自定义3个道具快捷位并随背包刷新数量

**Blocked by：** ST04-01的权威背包视图及结果恢复能力；不依赖ST04-02，二者接口稳定后可并行，但共享入口修改需串行集成。

**交付：** 玩家从背包拖入合法消耗品绑定、替换或移除快捷位；绑定模板而非stackId，背包整理、数量变化后显示仍正确。

- 固定3位，验证索引/可绑定模板/归属；不允许装备或复活纹章进入普通用药路径；清除绑定不删除物品。
- 同模板可用数量按背包合法堆汇总，耗尽显示0且保留绑定、补货自动恢复；数量变化不得由快捷位再维护第二份资产余额。
- 模板绑定与整理后stackId无关；用药消费优先角色绑定→账号绑定→未绑定的合同留给ST13实现，本任务提供相应读模型兼容测试，不伪造战斗药效/CD服务。
- 绑定命令与原结果、必要角色版本更新同笔；客户端拖入、替换、清除具备提交中/未知/失败和低版本保护；任何失败不消费道具。
- unit/contract/内存integration验证索引越界、非法模板、越权、重复/异参、并发绑定与整理、清空后补货；演示本地状态连接，真机拖动与正式传输另记录GAP。
