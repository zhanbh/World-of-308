## 01：评分排行服务核心、索引排序与分页查询协议

**Blocked by:** 无，可立即启动（待整体确认）。

**交付：**
构建 `RankingService` 服务核心并接入 `ranking.list` 协议处理；建立基于 `(score DESC, scoreReachedAt ASC, characterId ASC)` 的三元组稳定排序索引；支持全服总榜（`all`）、战士职业榜（`warrior`）与猎人职业榜（`hunter`）；实现有界游标编码与解码（单页 1~50 条，默认 20 条，页游标携带签名与页上界）；查询完全只读，不修改角色达到时间。

**验收：**
稳定三元组排序单元测试通过；同分保持时间测试通过（分值变动 500→600→500 重新计时）；游标翻页跨页去重测试通过；非法 scope、非法游标、超额页大小严格拒绝；查询过程中角色 `scoreReachedAt` 绝对不变。

## 02：短租约原子刷新缓存、TTL 新鲜度机制与并发抢锁

**Blocked by:** 01。

**交付：**
首屏榜单确定性键独立缓存（`rankCaches`）；配置 15 秒 TTL 新鲜期与 60 秒最大回退期（`stale: true`）；实现 3 秒短租约与版本 CAS 抢锁刷新机制；在多并发请求穿透时，仅抢到锁的单个调用执行底层直读刷新，未抢到锁者安全读取旧缓存或有界直读，防止高并发缓存击穿。

**验收：**
15 秒以内返回 `stale: false`，15~60 秒之间返回 `stale: true`，超过 60 秒触发强制刷新；多并发竞争短租约测试通过；缓存写入失败时不回滚任何装备事实。

## 03：本人名次三段式精准计数与大容量降级熔断

**Blocked by:** 01。

**交付：**
实现当前登录角色在排行榜中的精准名次聚合算法：通过三段互斥索引条件（比本人分高、同分但达到时间早、同分同秒但 ID 较小）进行 count 统计并加 1；关联返回 `ownRank`、`scoreReachedAt` 与 `rankAsOf`；在底层聚合能力受限、超时或超额时，优雅降级返回 `ownRank: null`（标识暂不可用），严禁伪造“未上榜”或全表扫库。

**验收：**
本人分段名次计算与全量排序排位 100% 严格一致；换装导致名次上升/下降即时反映；模拟 count 失败时降级返回 `ownRank: null`，列表与本人分数照常可用。

## 04：Cocos 排行榜面板与纯模型协调器

**Blocked by:** 02, 03。

**交付：**
构建纯模型协调器 `RankingCoordinator.ts`，维护完整的关闭、加载、就绪、翻页中、失败等状态机；具备代次隔离机制（`generation`），页面关闭后立即停止轮询并过滤在途延迟响应；实现 Cocos 交互组件 `RankingPanel.ts`：支持全榜/职业榜选项卡切换、列表滚动触底翻页、本人排名悬浮行置顶、缓存新鲜度（实时/已缓存）标识与错误重试。

**验收：**
协调器状态机与代次隔离测试全部通过；翻页数据按 characterId 幂等去重；断网或未知响应友好展示恢复重试；Cocos 离线构建通过。

## 05：换装/强化即时刷新联合验收、物理预算与两轴评审

**Blocked by:** 04。

**交付：**
构建端到端大闭环联合验收套件 `backend/test/ranking-joint-acceptance.test.mjs`：
1. 真实换装（ST05）/强化（ST18）→ 评分与达到时间变动 → 排行榜投影即时更新 → 打开榜单即时呈现名次变化大闭环；

3. 并发换装/出售与排行查询的 OCC 安全竞争；
4. 交付全量 7 阶段自动化门禁（`tools/check-all.cjs`）；
5. 产出 Standards 独立评审与 Spec 独立评审报告并归档。

**验收：**
端到端大闭环测试 100% 通过；物理事务与传输预算合格；全量回归 0 失败；双轴独立评审无违规偏离。
