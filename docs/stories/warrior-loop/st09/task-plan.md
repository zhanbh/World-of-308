ST03服务地点/上下文、ST04容器与整理、ST05装备/评分、ST06钱包及商店、ST07/08邮件/批领的本地代码均在当前分支，不再误读旧故事卡proposed为实现不存在。银行硬依赖ST03/ST04本地能力已具备；复用现有Store/会话/原结果/钱包结构，不以mock替代真实上游。

## 建议任务

### ST09-01：到银行打开个人/账号金库

**Blocked by：** 本故事内无；外部已具备ST03/ST04。

**交付：** 从合法银行服务上下文读取左右两侧，显示左库右包5列独立滚动；个人/账号单页签互斥，当前页签容量、已用与锁格正确。先交付可真实读取的Cocos银行面板，不提供固定成功按钮。

- 可信身份、当前会话/选角、角色/银行上下文代次与地点授权；离开银行/旧上下文/他人角色拒绝，背包不借路径绕过库权限。
- 个人库本角色20格起，账号库本账号100格；账号库不能返回背包或个人库；查询裁掉内部身份和流水正文。
- 页签切换取消选择/拖动，旧响应不得覆盖另一页签或另一角色；加载/明确空/失败与关闭可用。
- 权威查询contract/真实内存service integration + 客户端状态/实际Cocos切页与滚动演示。第二角色只作为隔离夹具，不引入猎人玩法。

### ST09-02：拖动堆叠物品存取并选择数量

**Blocked by：** ST09-01。

**交付：** 左库右包拖动后弹选量，默认整叠，确认提交；取消不发写请求，成功后刷新两容器。

- 同模板版本/绑定归属兼容才填充，每堆≤20；非法数量/不同账号/角色绑定进账号库拒绝；本角色绑定允许个人库，存取不改绑定。
- 所选数量不能全部容纳时整笔拒绝，提示可容纳量，不能部分转移或部分扣减。个人/账号页签不能串操作，不增加金库整理或任意跨库直转。
- 原子两容器、余量/输出traceRef与一笔有界J、A/O；全量数量与绑定池守恒，不递归追源，不留下两份余额。
- UI提交中防重；未知关窗重开沿原ID确认或显式重发原意图，不换ID；并发、每写点失败、迟包、来源变化、部分堆空间边界验证。

### ST09-03：整件装备存取与共享持有范围同步

**Blocked by：** ST09-01；不依赖ST09-02，接口稳定后可独立验证。

**交付：** 装备跨左右面板拖动整件存取，服务端确认前不提前移动；穿戴中装备不能直接存库，先通过既有穿脱功能入包。

- 双容器slots与实例location/version同笔；不复制装备payload，不改变词条、强化、耐久或绑定；目标满拒绝，无物品丢失/复制。
- 当前角色内部个人库↔背包总持有不变；背包↔账号库按实际物理scope移动同步持有摘要，其他角色私物不计共享；非套装不凭空加持有键。
- 所有权限与服务上下文持续重验，结果未知沿原请求；同ID异参、旧版本、并发相反方向、每写点故障及跨scope回滚有断言。
- Cocos整件拖放演示、换页/关闭取消和错误反馈；ST05/ST06正常合法资产到银行的实际内存组合验证，不用只有孤立空容器的测试声称兼容。

### ST09-04：背包/个人库分档扩容及金额确认

**Blocked by：** ST09-01及既有钱包能力；不必等待02/03全部实现。

**交付：** 从背包锁格/扩容入口或银行个人库锁格读取报价，明确容量变化与金额，选币后确认、服务端原子扣款解锁，再刷新容量与余额。

- 背包仅金币且城镇可扩；个人库只在银行、金币/点券择一；都每次+20至100，同档并发只扣一次；账号库100全开不卖扩容。
- 配置版本与quoteRef/目标stage/钱包及容器expected匹配；价格缺失/变化、余额不足、越级、已解锁/满容量拒绝；不以已确认兑换比推导价格。
- 同笔钱包/容器/原结果/流水/账号栅栏；失败不扣款不解锁，原请求重放不再扣款。UI确认取消无写、未知不第二次支付，显示实际所选一种币。
- 背包与个人库各阶段/两币配置、并发双币抢同档、每写点故障和关闭恢复验证；实际Cocos锁格/报价/确认/满容量演示。
