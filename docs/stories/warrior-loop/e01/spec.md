# E01／B0：协议、配置与检查基础实施规格

2026-10-22。用户已确认本地任务粒度与依赖图：01→02→{03,04,05,06}→07。采用仓库本地追踪，无Jira、外部链接、SP或虚构排期。此文件细化E01交付范围，不替代主题规则正文。

## 问题与目标

现有共享协议仍为v1并包含自报死亡/击杀与单次enterRoom，客户端检查存在隐式npx下载路径。本片建立可导入、可验证、可重复检查的v2公开合同及最小配置样本，保持旧实现可识别，不把类型迁移当真实业务完成。

权威入口：[主题索引](../../../backend/source-of-truth.md)、[B0范围](../../../design/implementation-b0-contract-foundation-v1.md)、[E01前置](../enablers.md#e01-协议配置与检查基础)。FR01～FR03最新合同优先于历史发现。执行基线为任务发布时工作区对应已确认合同，不把a286c04旧时间字段误作最新冻结版本。

## 交付边界

- E01-01～07分别交付检查入口、精确值编码、登录会话协议、输入恢复协议、资产服务协议、配置样本及联合验证。
- 03～06只实现协议/配置/校验及真实消费者contract harness，不实现对应业务服务；不允许返回固定成功的假处理器。
- v2 schema拒绝自报HP/击杀/奖励及单次enterRoom旁路；旧v1仍可用于历史内存切片测试，但正式v2入口不能转发给旧GameService伪装已实现。
- 正式身份、资产原子编排、战士伤害重算、真实SDK、Cocos场景接入在后续业务故事/E02；本片不创建云环境、不安装云SDK、不部署。
- 工具链首先发现本机已装Node/Creator及编译器，记录精确路径和版本；无满足要求的编译器时提交具体依赖方案，不隐式联网下载或静默降低类型检查强度。

## 完成标准

1. 各公开协议家族均有正/负样本，验证对象形状、范围、重复expected、版本/未知命令及公开私有边界；状态/归属等需要真实业务的校验标注后续责任，不能只做schema就宣称安全验证完成。
2. JSON与精确值编解码、HP/MP回复余数、规范化hash基础值往返可复现；不把编码工具算作完整算术/调度内核。
3. 最小战士测试release及非法配置有明确引用和版本，猎人profile不开启，所有候选数值标测试用途，不直接读取Python脚本作运行配置。
4. 可用单一检查入口执行类型、shared、旧后端有效回归及客户端模型，缺工具明确失败；不跳过失败套件得到假绿。
5. 07记录实际代码/配置/工具版本、命令及结果，原型/业务迁移GAP与后续故事责任清楚。没有SDK/真机证据不得标在线闭环完成。
