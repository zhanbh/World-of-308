# 正式背包与装备详情的 UI 样式落地

2026-11-09。分支 feat/inventory-ui-style，基线 feat-1.0.0 / fff0b74。用户已确认小样通过，并授权继续接入真实背包与装备数据。已验收小样完整保留在 feat/ui-slice-kit-preview / aa27196，本轮不把其模拟数据和验证场景迁入正式场景。

## 本轮边界

- 既有 ST04/ST05 上的表现与只读详情增量：56×56 格子、原生48×48图标、独立品质框/强化角标/耐久条/数量标牌，以及紧凑卡→完整详情。
- equipment.get 沿用当前严格 DTO。详情只接受仍在当前背包中的实例，核对槽位/装等/品质摘要、绑定角色、位置及响应装备版本；关页、切角或整理后忽略旧响应。
- 详情读取最多4个并发，仅请求可见装备并缓存至当前背包版本；读取失败独立重试，不写入资产、不改变原操作恢复状态。
- 整理、快捷位、金币扩容和 unknown 原操作恢复沿用 InventoryCoordinator。原按钮鼠标/模拟触摸重复取消问题、格子点击坐标偏移和末行裁切在本轮修正。
- 当前公开装备 DTO 未包含模板基础属性、NPC回收价、套装有效件数或激活效果。本卡完整展示已返回的词条、强化实际增益、绑定、耐久、套装名称及来源类别，其他行等待权威读模型提供，不填样本值或推算套装效果。
- 正式品质只映射白/绿/蓝/紫/橙五档；小样史诗示意不会成为新增业务品质。仅武器/耳环显示强化，只有启用磨损的七槽显示耐久数值；0耐久用数值和颜色表达。

## 运行

    node client/tools/preview-inventory.cjs

http://127.0.0.1:8775/?inventoryPreview=1&inventoryPort=8792 自动打开背包。界面连本机8792端口的真实 Login/Character/Inventory/Equipment/Bank 服务，隔离 MemoryStore 以8格fixture引导，账号与数据均为临时数据。明确指定本机服务时连接失败会报告错误，不退回沙盒。

第0格白装、第4格长名16词条/+10/0耐久武器、第7格无耐久戒指用于检查。药水初始拆堆，可整理合并；快捷位显示同模板总量；锁格触发原金币报价确认。扩容取消不提交。关闭详情优先使用 Esc，再次 Esc 关闭背包。

试玩服务会保留本次进程内的操作结果。本轮浏览器验收后当前数据为6/40格、第一快捷位生命药8瓶；重启该临时服务可恢复初始8/20格。

重建用 --rebuild，使用本机已有 Creator 3.8.8，无安装与云部署。微信构建沿现有 build-wechat.cjs；无本机 HTTP 连接时的离线展示明确为沙盒，不能当作服务端实机验收。
