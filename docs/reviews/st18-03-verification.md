# ST18-03 实施与验证

日期：2026-11-02
范围：跨装备会话记忆复用、相似距离衰减与部分消耗、角色代次边界重置与隔离、未知请求/固定样本恢复、Cocos 传输协调器高段/纪念品/损毁联动及真实 OCC 竞争防错。来源为已批准 [ST18 规格](../stories/warrior-loop/st18/spec.md)、[03 实施任务](../stories/warrior-loop/st18/issues/03-memory-recovery.md) 及 [开发真相源](../backend/source-of-truth.md)。本报告只记录 ST18-03。没有创建、同步或回填 Jira。

## 实现

1. **`EnhancementCoordinator` 客户端协调器演进**：
   - 移除了原低段 +10 截断（`LOW_GRADE_LIMIT`），全面支持 11～20 级强化流程，当强化等级到达 20 级时正确标记 `MAX_GRADE_REACHED` 并置空报价；
   - 增加纪念品选用支持（`setMemento(enabled)` 与 `enhance(useMemento?: boolean)`），目标等级 $\ge 11$ 级时按状态向服务端申请包含纪念品材料费用的报价与提交；
   - 完善装备永久损毁后的生命周期处理：当服务端返回 `destroyed` 结果时，协调器自动清空本地持有的 `itemId`、`view` 和 `quote`，状态重置为 `empty`，避免客户端再次发起查无此装备的非法请求；
   - 调整本地持久化键名为 `['enhancement', sessionId, sessionEpoch, characterId, rolePlayEpoch]`，统一覆盖低段与高段；
   - 增强未知意图与网络丢包恢复（`recover()`），通过 `operation.get` 区分 `found`（重放原结果并推进本地版本）与 `notFound`（沿原 tuple 幂等重发），关闭面板时递增代次优雅退休迟包回调。

2. **跨装备相似记忆与衰减机制验证**：
   - 强化记忆归属于 `characterId` 与 `rolePlayEpoch` 维度，武器强化失败累积的记忆可直接无缝加成耳环等其他合法部位；
   - 严格按照不可变配置中的整数距离权重数组（`distanceWeights`）计算贡献与成功消耗：
     - 同级（距离 0）：100% 加成贡献，成功后 100% 消耗清空；
     - 邻级（距离 1，权重 60%）：60% 加成贡献，成功后按 60% 消耗并保留剩余 40%；
     - 邻级（距离 2，权重 14%）：14% 加成贡献，成功后按 14% 消耗并保留剩余 86%；
     - 远级（距离 $\ge 3$，权重 0%）：0% 加成贡献，成功后 0% 消耗，原有记忆 100% 完整保留；
   - 严格落实多重上限封顶机制：单来源上限 `memorySourceCap`（150000）、总加成上限 `memoryTotalCap`（150000）以及全链路概率上限 `probabilityCap`（900000）。

3. **代次边界与并发幂等保护**：
   - 同一角色短恢复、城镇移动、面板关闭或服务实例重启，已提交记忆保持持久有效；
   - 重新登录或会话代次递增（`rolePlayEpoch + 1`），自动初始化全新的零记忆，老代次记忆不继承并保留存储审计；不同角色间记忆绝对隔离；
   - 秘密随机数样本基于 `[accountId, operationId]` 确定性生成，在 OCC 事务重试中保持稳定不变；提交后凭据永久保存在 `Receipt` 与 `AssetJournal` 中，即使后续服务端配置参数变动，原请求依然幂等返回历史原结果；
   - 强并发保护：强化执行前与穿戴卸下、商店出售等生命周期变更进行版本栅栏校验，发生并发竞争时整笔拒绝，零扣款、零扣料；
   - 严格信息安全隔离：公开 DTO（`service.quote`、`enhancement.get`、`operation.get`）与单据结果均不泄露内部随机样本、阈值及记忆详细数组。

## 验证证据

- **新增定向与边界测试套件**：`backend/test/enhancement-memory-recovery.test.mjs` **10/10 全部通过**：
  1. 跨装备记忆复用：武器失败累积记忆，耳环成功消费并清空对应档位；
  2. 相似度距离衰减：同级、距离1（60%）、距离2（14%）、距离5（0%）的分档加成与精确整除消费；
  3. 上限控制：单档位源上限、总记忆加成上限及全链路概率上限（`probabilityCap`）严格截断；
  4. 会话与代次边界：`rolePlayEpoch` 切换生成新零记忆文档，跨角色绝对隔离；
  5. 固定随机数与重试：OCC 重试下随机数种子与样本绝对一致，拒绝重抽；
  6. 幂等性与不可变结果：重放原操作或通过 `operation.get` 幂等获取结果，零二次扣款；
  7. 协调器高段支持：+11 级报价正常响应、纪念品动态切换、装备损毁后本地状态平滑重置；
  8. 协调器丢包与恢复：模拟服务端已提交丢响应（`found`）与服务端未收到丢请求（`notFound` 自动重发）双路径恢复；
  9. 真实并发防错：装备卸下或出售与强化并发时准确触发版本拒绝，杜绝幽灵扣款；
  10. 信息安全隔离：报价与查询接口不泄露私有随机样本或记忆数组。
- **强化全家桶测试**：低段（24 项）+ 高段（8 项）+ 记忆恢复（10 项）共 **42/42 全部通过**。
- **关联回归集合**：覆盖装备、单件修理、商店买卖、银行存取、邮件服务、掉落领取与终局结算共 **122/122 全部通过**。
- **代码与格式门禁**：`git diff --check` 通过，无空白字符异常。
