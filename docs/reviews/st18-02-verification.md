# ST18-02 实施与验证

日期：2026-11-02
范围：11/12失败降到+10；13–20失败损毁；主动纪念品消耗；返还与满包邮件；套装持有/装备属性/评分；与真实商店及邮件服务交互。来源为已批准[ST18规格](../stories/warrior-loop/st18/spec.md)、[02实施任务](../stories/warrior-loop/st18/issues/02-destruction-memento.md)及[开发真相源](../backend/source-of-truth.md)。本报告只记录ST18-02。没有创建、同步或回填Jira。

## 实现

- `EnhancementService` 支持1–20级报价；保留1–10规则。11–12失败降至+10并重算强化AP，13–20失败将装备改为retired/destroyed并从角色装备栏或背包移除。
- 主动使用纪念品加入报价材料、验证角色绑定来源并按配置消耗；成功/失败均扣。固定原意图抽样、失败记忆、O/J和资产同一事务。
- 损毁装备保留原sourceKey/sourceLocator。已穿戴目标同步有效属性、stats/equipment版本、固有评分及排行榜；适用套装同步减少角色持有汇总。
- 返还先消耗材料与选用纪念品、移除背包里的损毁实例，再填已有纪念品叠加、新建空格堆叠，余量生成单附件30天角色邮件。邮件通过既有MailService领取；没有新增可领余额。
- `EquipmentEntity.location`与公开视图补齐retired位置来源。local-test配置显式覆盖高段概率、金币/AP、纪念品成本/增益/返还；正式数值未定，15–20率及纪念品表中的夹具值仅为候选。

## 验证证据

- 高段和低段定向测试：32/32通过，覆盖11/12降级、13–20每一档损毁、纪念品成功率严格边界、缺少/错误绑定纪念品、背包目标腾格、出售与损毁先后、邮件溢出与真实领取、迟包幂等。
- 满100格样本，套装穿戴装备损毁且返还5个纪念品：唯一读取14、唯一写入11、Transaction get/set合计25次、序列化写集28023字节、最大单文档15930字节。满包时1个返还填入已有19/20堆，剩余4个进入邮件。11个物理写点均逐项注入故障并验证MemoryStore快照完全不变。
- 相关回归108/108通过：装备服务/规则、邮件、商店/规则、银行、掉落领取、终局结算。
- 后端项目TypeScript 5.8.2 `tsc --project backend/tsconfig.json --noEmit`通过；`git diff --check`通过。
- Node24原生`node --test`尝试运行时，宿主禁止runner spawn子进程（`spawn EPERM`）；同一Node24版本在单进程中直接导入这些Node test模块，全部断言已运行并通过。这是执行环境限制，未下载安装/替换依赖。

## 边界

仅MemoryStore本地事务证据，不等于真实SDK的事务/重试/费用/字节验证。正式高段概率及纪念品成本/增益/返还量仍待数值设计；没有运行Cocos、手机或云资源验证。ST18-03跨装备记忆、04 Cocos面板、05完整联合验收及独立最终代码评审仍未完成。
