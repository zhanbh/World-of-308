# 低修正恢复方案比较 v1

日期：2026-10-21。状态：历史候选比较。用户后续明确允许秒级回溯，采用原结果查询与检查点恢复；持久输入收据方案不作为本期必需架构。无实现或网络验证。

## 1. 先区分三种“未确认”

| 情况 | 可用证据 | 可减少修正的处理 |
| --- | --- | --- |
| 操作已提交，仅成功响应丢失 | 原操作和权威检查点已持久化 | 查询原结果即可保留，不能误回旧位置或重复消费 |
| 输入已在服务端持久接收，尚未算完/提交业务效果 | 有界输入原文、摘要、接收序号/时间与场景代次 | 在合法时间前沿内继续验证；不能仅因没回包就丢输入 |
| 输入只在客户端、服务端从未接收 | 无可信接收时间，客户端时钟不可靠 | 单凭恢复后补报无法证明是断线前输入；不承诺保留全部预测 |

“已接收”不等于合法或成功，也不允许直接发奖。第一种是已有防重恢复要求，不是新增宽松验证；第二种需要新的持久输入收据，第三种仍是根本限制。

## 2. 候选比较

| 方案 | 体验 | 安全/成本与限制 |
| --- | --- | --- |
| A 最后确认检查点直接修正 | 最易落地，但响应丢失或排队时可能多退进度 | 用户暂不接受，不作默认方案 |
| B 持久接收输入＋及时等待＋验证后恢复（建议） | 保住已送达的合法在途输入；弱网时较早停住，减少积压后大幅拉回 | 增加输入收据写入/恢复复杂度；仍不能保证未送达输入零修正 |
| C 断线后补报本地输入 | 网络表面最顺，但可在离线期间生成/修改输入 | 与已定不允许离线刷怪和可信行为目标冲突，不建议 |
| D 每次动作等服务端批准再表现 | 减少预测分歧 | 延迟直接落到移动/攻击，仍有响应丢失，破坏即时手感，不建议全面采用 |

## 3. 建议B的具体行为

正常客户端即时表现，输入连续发送。服务端对有界输入持久接收后给出“已接收”收据，再验证/原子提交动作、资产和新检查点；实际能否合并两步以省写入需测量。不得仅为了回一个快ACK，在输入未持久化时声称可恢复。

客户端显示两个内部游标：已持久接收前沿、已验证提交前沿，不向玩家展示技术序号。超出未送达或未验证积压窗口，或明确断网/切后台时，停止新增战斗预测并显示“网络不稳定，正在同步”。持续按住的旧输入不能跨恢复自动重放为新攻击；重新取得有效状态后恢复正常输入。

恢复时先查原操作、接收收据和检查点，再按序完成已持久收到且仍合法的片段；结果与预测一致则原地续接，只有状态差异才修正。收到但尚未验证的奖励不提前视为到账。保持“已确认资产/收益不撤销”规则。

允许继续验证的仅是暂停前可信接收边界内的输入；收据时间不能让过期场景复活，不能延长死亡/恢复截止。接收和暂停竞争须共用场景代次/控制版本，原子封住可接收前沿；迟到片段不能靠旧收据重开场景。处理慢导致截止竞争如何判定仍需专项审查，不在本稿暗中给予额外恢复时间。

## 4. 不能隐瞒的限制

如果最后一步从未到服务端，又要求严格不接受离线补报，就无法同时保证这一步绝不修正；把输入签名、客户端时间或提前发的随机种子加进去也不能证明输入真的生成于断线前。可优化的是丢失范围与频率，不应向用户承诺绝对零拉回。

“提前等待”本身会让弱网中更早停住，窗口太短频繁卡住，太长积压增大；具体毫秒值必须依据Note20 Ultra与实际链路验证。恢复10秒仍沿既定规则，不能因内部队列排队自动延长。

## 5. 需要的后续设计与证据

输入收据逻辑实体：场景/代次、seq范围、摘要、服务端接收时间、有限输入内容或不可变引用、received/validated/rejected状态及原操作关联；只可由服务端写入。它不替代operations、资产来源或检查点。

必须验证响应丢失、已接收未处理、仅本地尾部、收据与暂停并发、超时清理、重复收据、同序异参，以及处理队列积压的费用/时延。额外持久接收＋业务提交可能增加写入，旧1200片段预算不能当最终事务数。完整事务与存储清理方案在用户选择后再细化，当前不宣布方案B已确认。

## 恢复体验最新确认（2026-10-21）

用户明确战斗表现不要求强一致，允许秒级回溯；短恢复先查询原请求结果，再以服务端最新确认检查点恢复，未确认移动/攻击表现允许修正。这不放松钱包、消费、发奖与原操作结果的原子性，已确认资产和收益不撤销。

持续无法恢复时显示「网络中断，请重新进入游戏」，停止继续战斗并要求重新进入；沿用既有10秒恢复窗口，不另增宽限或自动续关。未通关超时失败/关闭并保留已保存收益，已通关仅关闭拾取场景、不撤成功；新launch默认旅店，不重启续关。客户端提示不单独改服务端结果，下一请求/清理仍按原持久截止处理。

此前为减少修正提出的持久输入收据不作为本期必需方案；采用原操作结果和权威检查点恢复。秒级是体验尺度，不保证任何弱网都只退1秒；必须限制未确认预测积压，超上界先暂停等待，不允许无限本地刷怪或离线补报。具体积压上界和时间锚点待工程验证。
