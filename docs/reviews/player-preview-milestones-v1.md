## 建议试玩节点

| 节点 | 玩家可以重点检查 | 必须同时具备 |
| --- | --- | --- |
| ST09之后的城镇界面联调包 | 背包整理/穿脱、买卖、邮件单领批领、银行存取/选量/扩容 | ST05～09相关Cocos界面实际挂接，串接真实本地服务，不只提供协调器测试 |
| ST12战斗版 | 副本进入、移动普攻/四技能、怪物血条/预警/精英Boss行为 | ST10～12与战斗HUD/场景接通；奖励闭环尚不作为该节点承诺 |
| ST15首本闭环 | 入本→战斗/药品→死亡复活→Boss通关→拾取/奖励→回城 | ST10～15真实组合，不能靠测试夹具自动报击杀代替 |
| ST16恢复版 | 断线/恢复、重复点击、弱网迟包、资产不重发 | 原操作结果/完整状态恢复已集成，手机与平台验证另记 |

不要等到ST20全部结束才让玩家首次操作；每个节点先交可玩的功能版，再迭代视觉，最终设备和经济验收仍需证据。

## 技能、怪物、副本还需要哪些设计

已有[UI稿目录](../design/ui-mockups/README.md)、[纠偏合同](../design/ui-review-authoritative-delta-v1.md)、[状态规范](../design/ui-state-coverage-v1.md)和战士动作原型，不是全部从零重画。静态PNG/HTML不等于运行时可点击UI，也不能覆盖已确认规则。

- 技能/战斗HUD：技能图标、解锁/低蓝/冷却、普攻/摇杆/四技能/独立饰品与3药位的布局和热区；接既有动作，不重新发明战士四技能。药品与饰品状态在ST13接入。
- 怪物：界面包括血条、精英/Boss标识、读条/危险预警及状态反馈；造型、立绘/像素图、移动/受击/死亡动画和攻击特效属于美术/战斗表现，不能混称一个“怪物UI”而漏设计。
- 副本：选择/难度/进入条件/加载/换房、战斗状态、死亡复活、通关及拾取/回城反馈；地图背景、边界与遮挡/碰撞是场景内容，随ST10～15落实，位移技能沿既定地图边界约束。

首轮优先可读、可操作与状态正确，再统一视觉品质，不把功能样板等同正式美术定稿。
