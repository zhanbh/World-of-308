# 308世界 — 动作原型规格

状态：**方案已确认；v0.6 Web Mobile H5 已构建，用户确认手机浏览器可以打开并操作。人物和动作表现仍不满意，单角色美术动作小样是下一步；这次 H5 测试不等于微信小游戏构建、剑气穿透验收或性能验收。**

实施进展：用户完成 Creator 3.8.8 安装后，已开始原型实现，见 [client 样板说明](../client/README.md)。对抗切片包含一种近战怪、单怪/三怪切换、锁定区域预警、玩家受击保护/僵直/击退，以及怪物受击闪白/僵直/击退。浏览器预览实测了单次普攻、摇杆横向跑动和预警区闪避；v0.6 Web Mobile H5 已由 Creator 构建，用户确认手机浏览器可以打开并操作。用户反馈人物与动作表现较差，因此新增[单战士动作小样美术 brief](art/warrior-animation-sample-brief.md)。v0.6 加入技能按钮、双刀两次快速横挥、扩散弧形剑气及逐怪单次伤害；初值为调试参数。类型与逻辑检查通过，但剑气对多怪的实际命中和穿透尚未完成专项验收。Note20 Ultra 微信小游戏构建、性能和整体验收仍未完成。

日期：2026-10-15。依据：本轮用户确认，以及[整体规格](spec.md)、[技术架构](architecture.md)、[路线图](roadmap.md)。本文件规定动作原型，不缩减最终战士、猎人两职业 MVP。

## 1. 验证目标与最小范围

回答：做多小的原型，就足以验证移动、攻击、受击和技能是否好玩？

最小循环：靠近 → 对准纵深 → 出招 → 看懂命中 → 识别反击 → 走位或突进 → 再次进攻。

| 内容 | 已确认范围 |
| --- | --- |
| 玩家 | 一个双刀战士，四阶段普攻循环 |
| 场景 | 一个固定镜头房间，有限纵深、脚底阴影与 Y 排序 |
| 普攻 | 左砍 → 右砍 → 上挑 → 双刀交叉横扫；连续输入才推进，断连后从左砍重开；保留按住循环 |
| 技能 | 正面范围斩击、短距离攻击性突进、扩散圆弧剑气；突进没有无敌 |
| 敌人 | 一种有明显攻击预警的近战怪，分别测试单只和三只 |
| 配套 | 血蓝、技能冷却、受击僵直与击退、短暂受击保护、死亡后一键重试、清场后非战斗恢复 |
| 单轮 | 约一分钟，可快速重复和调整 |

临时素材需足以辨识朝向、四阶段普攻、剑气扩散边界、命中和受击；刀光、命中音与短暂停顿可作为反馈调节项，不以精修素材作为入口条件。

扩散圆弧剑气为原型第三个技能，并已确认替换最终战士技能表中原有的“周身持续范围攻击”。MVP 仍为四个职业主动技能，重击大招留后续实现。

不接入装备成长、掉落奖励、背包、完整副本、猎人、完整四职业技能与饰品、药品系统、登录、后端和永久资产。原型仅使用本地临时状态，不改变正式游戏的在线异步架构、服务端资产权威和断网暂停规则。

双刀是本轮确认的战士视觉与动作方向，覆盖此前双手剑表述；不因此新增第二个武器装备槽。两刀如何映射装备实例、武器模板和强化，留装备模块设计。

## 2. 引擎与目标设备

- 引擎：**Cocos Creator 3.8.8 + TypeScript**，原型期间固定版本；采用此版本不代表已经安装或验证。版本依据为 [Cocos 官方下载与版本说明](https://www.cocos.com/creator-download)。
- 首台验收设备：**三星 Galaxy Note20 Ultra**，以微信小游戏真机运行结果验收。
- 目前结论仅覆盖实际测试设备，不将该机称为最低支持机型，不推定已覆盖其他 Android 或 iOS。
- 开始测试时记录具体型号/芯片版本、系统、微信版本、游戏构建版本和测试条件；用户仅提供了系列型号，不能预填这些信息。

## 3. 横屏与像素样板

- 横屏，基础战斗画布 **480×270**；UI 独立适配屏幕、安全区和微信界面遮挡。
- 先试小人物：本体高约 **32–40 个源像素**，双刀和刀光允许超出本体。
- 该比例是已同意试验的起点，允许根据真机辨识结果放大人物或收紧视野，不是生产素材尺寸承诺。
- 首轮浏览器试玩反馈：用户认为人物可再大一点、移动速度可用，攻击表现不自然。v0.2 先将人物显示比例增加约 20%（待机本体约等效 44 源像素），保留移动速度；通过身体发力、双手配合、各段挥刀轨迹与收势改善空挥。该调整尚待用户复评，不视为真机验收通过。
- 使用统一脚底锚点，以地面位置决定碰撞、纵深与 Y 排序；视觉特效不直接充当命中范围。
- 像素素材采用最近邻采样，优先整数倍显示；必要时留边，宽屏可扩展背景。适配不能改变移动与攻击的空间规则。
- 战斗画布、UI 逻辑布局与设备实际渲染分辨率分别处理；不将整屏文字压成 480×270。
- 逻辑位置保持连续；显示像素对齐方式以不产生明显移动抖动为检查项。完整帧框、帧数和动画帧率仍为可调整样板参数。

## 4. 移动与触控

### 4.1 左侧摇杆

左下固定底座虚拟摇杆，支持任意输入方向。移动不采用四方向锁定，也不对最终斜向速度作统一归一化。

- X 轴：根据摇杆横向分量大小变速，轻推慢走，推到底跑；横向死区内不移动。
- Y 轴：纵向分量越过死区后，以固定速度向上或向下移动；该速度不随力度及横向走跑状态变化。
- 斜向同时应用两轴分量。对合成速度归一化会改变固定 Y 轴速度，因此不采用。
- Y 轴速度独立于 X 轴最大速度配置；具体速度、死区、横向曲线在原型中调试，不视为已确认数值。
- “Y 轴固定”描述自由移动输入规则；出招锁定、受击、击退、突进和场地边界可按相应状态限制或替代移动。

### 4.2 朝向与按钮

- 横向输入改变左右朝向；纯纵向移动保留原朝向。人物先使用左右朝向，不要求八方向动画。
- 右下大普攻键，范围斩、突进、剑气三个小按钮排在其左上方；新增按钮后重新检查间距和遮挡。
- 支持移动与攻击/技能同时触摸；松手、触摸取消时释放对应输入，不能出现卡键。
- 按钮均应在安全区内；实际尺寸与间距按 Note20 Ultra 正常双手握持调整。

### 4.3 角色动作参考规范

用户指定以其描述的 **Codex 宠物交互表现**作为动作设计参考：拖动宠物时，可看到左右移动、站立、转向、跑跳及动作切换。这里记录的是用户提供的参考描述，尚未检查该宠物的实际代码、素材或技能实现。

原型需体现以下表现要求：

- 待机时有可辨识的站立动作；开始移动、改变方向、走跑切换及停止时，动画与角色状态一致，不能只平移一张静止图片。
- 左右运动时正确更新朝向；纯纵向移动继续遵守保留朝向的规则。停下后保留最后朝向。
- 横向慢走与跑动有可辨识的姿态或节奏差异，动画步频与实际速度协调，避免明显滑步；纵向仍按已确认固定速度移动，不因动画切换改变速度。
- 起步、停步及转向切换自然且响应及时，不能为等待动画结束而额外拖延摇杆响应；攻击与受击仍遵守各自状态限制。
- 跑跳作为身体起伏、重心和动作衔接的参考。当前原型仍无主动跳跃按钮、平台跳跃或空中连招；动画中的视觉起伏不改变脚底地面位置、纵深、碰撞或受击资格。若要增加真实跳跃机制，另行确认范围。

可复用的设计组织方式是“输入意图 → 运动/战斗状态 → 朝向与动画表现”，输入源保持可替换；游戏使用虚拟摇杆，不引入拖动角色或宠物自主游走。具体状态优先级和动画过渡参数在实现时细化。

若后续发现可访问的宠物逻辑、skill 或资源，先检查适用范围、接口、运行环境和许可，再判断是否可复用；本条不声明已经取得这些资源，也不将宠物 skill 作为 Cocos 游戏运行依赖。无法直接复用时，在 Cocos 中实现同类动作表现即可。

## 5. 动作与对抗

- 普攻按“左砍 → 右砍 → 上挑 → 双刀交叉横扫 → 左砍”四阶段循环。每次单击只请求下一阶段，不因首次单击自动执行整套；没有衔接输入就停在当前动作结束，断连后下一次从左砍开始。
- 第四段替换原下压收招：双刀同时横扫，先左手向右、右手向左交叉，再左手向左、右手向右反向展开后收势。交叉与展开均属于同一次第四段动作，不额外要求输入，不新增普攻阶段；两把刀都显示各自轨迹，不自动推导额外伤害次数。
- 第四段收势调试：用户反馈收招过快，并指定《三国战纪》张辽为动作参考。v0.4 先将第四段从 460ms 延长为 760ms，保留快速横扫，在交叉、展开处留停顿，再缓慢回收；完整动作结束后才开启 300ms 衔接窗口。参考视频访问受限，尚未逐帧核对，不将此调试值称为原作参数或已确认最终值。
- 连续普攻的衔接间隙先取约 **300ms**，是用户提出的可调初值，不是四阶段总时长，也不是各刀固定间隔。衔接超时即重置连段。
- 已确认计时起点：从本段动作完成、允许再次出招时开始计算约 300ms 的衔接窗口；动作期间的提前点击由输入缓冲处理。不按两次按下的时间差计算断连。
- 保留此前按住普攻的约定：按住时在允许衔接的时点持续请求下一阶段；松开不继续产生请求。单击不排入整套，缓冲最多保留下一阶段的一次请求作为调试建议，避免快速连点排队执行多套动作。
- 上挑与双刀交叉横扫先表示动作方向，不自动增加浮空、跳跃、倒地或额外控制机制。
- 受击打断或实际释放技能时重置普攻连段，下次普攻从左砍开始；不将未成功释放的技能按钮输入视为已释放技能。
- 出刀时短暂限制移动，后摇末段恢复移动；允许提前输入下一次攻击。缓冲窗口、可取消时点与技能衔接优先级是调试项。
- 攻击向人物面前释放并覆盖一定纵深；攻击有效阶段锁定朝向。前摇中可否转向留作调试项。
- 范围斩验证正面范围压制与较强反馈；突进验证接近、脱离和移动攻击衔接，没有无敌，不代替主动闪避。
- 技能暂称“扩散圆弧剑气”：角色快速连续横向挥动武器两次，然后生成一道具有一定覆盖范围的圆弧剑气。两次挥动是出招动作，不是每次挥动各发射一道剑气。剑气动态向外扩散，到达最大范围后消失，受波及的怪物均受到伤害。
- 剑气可穿过多个怪物，不会被某只怪物挡住或在命中后消失；这里的穿过怪物不是忽略护甲的穿透属性。
- 剑气的圆弧角度、初始/最大范围、扩散速度、同一怪物的命中次数及频率仍待设计；两次挥动本身是否另有近战伤害也未确认。可见剑气与伤害判定的范围、时机必须一致，不能默认整个圆弧内部或每个渲染帧都重复结算伤害。
- 职业技能使用魔法并有冷却；具体消耗、伤害、范围和动作时长不在本轮锁死。
- 怪物先预警，再进入承诺阶段并锁定目标或区域，不持续追踪转向；玩家走出攻击区可避开。
- 普通怪提供僵直/击退反馈；玩家有短暂受击保护，避免密集攻击形成不可脱离的连续受击。
- 血蓝、死亡重试、清场恢复使用临时配置，不推导正式成长和经济数值。

## 6. 验收场景

以下均为待执行的验收，不表示已经通过。

### 浏览器与手机试验记录（2026-10-15）

- 已验证：预览能显示房间、战士和怪物；一次空格输入能挥刀并扣除怪物生命；拖动左摇杆能横向跑动；出现红色锁定区域后跑出区域，攻击落空且玩家未扣血。当前单怪近战循环有可读的预警和闪避反馈。
- 手机观察：用户确认手机浏览器可打开并操作 Web Mobile H5；当前人物与动作表现仍较差，尚未达到基本手感验收。该结果来自手机浏览器，不是微信小游戏包，也没有记录 FPS 或完成 10 分钟稳定性测试。
- 未验证：普攻四阶段的完整时序、300ms 边界、受击僵直/击退的主观手感、三怪压力、技能视觉和穿透。浏览器控制台未见错误或警告。
- Cocos 编辑器预览曾显示旧页面，不能用它代表 Web Mobile H5；手机 H5 已单独确认可运行。剑气的多目标穿透、命中次数和视觉判定仍需专项验收。

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| P1 | 横向轻推、重推，纵向不同力度，组合斜向 | 横向走跑可辨；纵向越过死区后定速，不因横向走跑改变；斜向不归一化 |
| P2 | 移动中按住普攻、释放技能，松手及取消触摸 | 多点触摸正常，无卡键；攻击锁定、后摇恢复和缓冲行为一致 |
| P3 | 正常握持距离观察单怪对抗 | 小人物仍可辨识朝向、四阶段普攻、剑气边界、出招、命中和受击；不依赖放大截图 |
| P4 | 前后错开纵深、左右换位和交错遮挡 | 命中范围能理解，未出现明显视觉砍中但判定落空的持续问题；Y 排序正确 |
| P5 | 怪物预警后走出攻击区，突进经过攻击区域 | 承诺后不追踪，走位能稳定避开；突进没有无敌，符合攻击判定时可受伤 |
| P6 | 单怪、三怪分别对抗，连续受击 | 僵直与击退反馈明确；短暂保护有效，不被立即连续锁死 |
| P7 | 消耗技能、死亡重试、清场 | 魔法与冷却可理解，死亡后一键重试；清场进入非战斗恢复 |
| P8 | Note20 Ultra 微信真机三怪战斗，包含剑气释放，连续游玩 10 分钟 | 目标 60 FPS，无明显持续掉帧或卡顿；记录帧率/帧时间与异常，不能只凭开发工具模拟器判断 |
| P9 | 用户连续体验几轮 | 普攻、范围斩、突进、剑气各有用途，用户仍愿意再试，并明确确认基本手感通过 |
| P10 | 单击、动作内提前点击、窗口内续点、超时续点、持续按住及完成第四段 | 单击不自动打全套；续点按左砍/右砍/上挑/双刀交叉横扫推进；动作内提前点击由缓冲处理；从本段动作结束且允许再次出招时起，以约 300ms 初值验证窗口内外边界，超时后从左砍重开；第四段后循环；按住可连续推进，松手不继续生成攻击请求 |
| P11 | 快速连续横向挥动两次后生成剑气，扩散经过不同距离的多只怪，直至消失 | 两次挥动后生成一道动态扩散的圆弧剑气；受波及怪物均按最终命中规则受伤，范围外及剑气消失后不受伤；不会被任何一只怪挡住；同一怪物不因渲染帧率不同而多结算伤害 |
| P12 | 普攻连段中受击打断或实际释放技能，再次普攻 | 原连段重置，下次从左砍开始 |
| P13 | 待机、起步、横向慢走/跑动、左右转向、纯纵向移动和停步 | 动画与运动状态一致；走跑可辨，停止后回到待机并保留朝向；无明显滑步或切换闪烁，无额外输入延迟；视觉起伏不改变地面判定 |

出现问题时优先调整移动曲线、人物比例、动作时序、攻击范围、反馈和布局，再重复对应场景。用户确认基本手感后，才以结论指导内容和在线基础闭环。

## 7. 验收边界与待调项

已确认的是上述 60 FPS 目标、连续测试和可感知验收条件。此前讨论过的六怪压力、P95 帧时间阈值、输入延迟阈值、多人评分等未纳入最终确认范围，不作为本次硬性门槛。

包体与启动时间应在首次样板构建时测量记录；本轮未确认数值上限，不沿用旧蓝图数字，不宣称已满足平台限制。动作原型通过不代表正式发布性能已通过，其他设备覆盖与发布门槛后续单列。

调试项包括两轴速度、死区、横向变速曲线、按钮尺寸、人物比例、动画帧框/帧数、攻击前后摇、输入缓冲、取消与衔接规则、约 300ms 的连段窗口、受击保护时长及技能数值。连段计时起点及受击打断/释放技能重置连段已确认；剑气的单目标命中规则、出招挥动本身是否造成伤害仍需细化。调试结果需留记录，不能把建议初值写成用户已确认结论。
