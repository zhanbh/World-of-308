## 1. 验证目标与最小范围

回答：做多小的原型，就足以验证移动、攻击、受击和技能是否好玩？

最小循环：靠近 → 对准纵深 → 普攻/技能出招 → 看懂命中 → 识别反击 → 走位躲避 → 再次进攻。

| 内容 | 已确认范围 |
| --- | --- |
| 玩家 | 一个双刀战士，三段普攻循环 |
| 场景 | 一个固定镜头房间，有限纵深、脚底阴影与 Y 排序 |
| 普攻 | 三段循环：交叉斩→反手上挑→下劈收势；连续输入才推进，断连后从A重开；保留按住循环 |
| 技能 | 十字斩、崩山击、拔刀斩、崩山裂地斩（大招）；不保留通用正面范围斩或独立短突进 |
| 敌人 | 一种有明显攻击预警的近战怪，分别测试单只和三只 |
| 配套 | 血蓝、技能冷却、受击僵直与击退、短暂受击保护、准备/胜败/手动再挑战、重试恢复血蓝 |
| 单轮 | 约一分钟，可快速重复和调整 |

临时素材需足以辨识朝向、三段双刀普攻、拔刀斩范围、命中和受击；刀光、命中音与短暂停顿可作为反馈调节项，不以精修素材作为入口条件。动作参考记录见[DNF动作参考](art/dnf-action-references.md)，参考视频和 GIF 只用于观察，不作为游戏运行时资源。

最新确定的原型技能组为十字斩、崩山击、拔刀斩和崩山裂地斩（大招）。取消原占位的正面范围斩和独立短突进，拔刀斩替代原扩散剑气；崩山击本身可以有跃起下砸动作，不增加通用突进按钮。MVP 仍为四个职业主动技能。

不接入装备成长、掉落奖励、背包、完整副本、猎人、完整四职业技能与饰品、药品系统、登录、后端和永久资产。原型仅使用本地临时状态，不改变正式游戏的在线异步架构、服务端资产权威和断网暂停规则。

双刀是本轮确认的战士视觉与动作方向，覆盖此前双手剑表述；不因此新增第二个武器装备槽。两刀如何映射装备实例、武器模板和强化，留装备模块设计。

## 2. 引擎与目标设备

- 引擎：**Cocos Creator 3.8.8 + TypeScript**，原型期间固定版本；采用此版本不代表已经安装或验证。版本依据为 [Cocos 官方下载与版本说明](https://www.cocos.com/creator-download)。
- 首台验收设备：**三星 Galaxy Note20 Ultra**，以微信小游戏真机运行结果验收。
- 目前结论仅覆盖实际测试设备，不将该机称为最低支持机型，不推定已覆盖其他 Android 或 iOS。
- 开始测试时记录具体型号/芯片版本、系统、微信版本、游戏构建版本和测试条件；用户仅提供了系列型号，不能预填这些信息。

## 3. 横屏与像素样板

- 横屏，基础战斗画布 **480×270**；UI 独立适配屏幕、安全区和微信界面遮挡。
- 先试小人物：本体高约 **32–40 个源像素**，双刀和刀光允许超出本体。
- 该比例是已同意试验的起点，允许根据真机辨识结果放大人物或收紧视野，不是生产素材尺寸承诺。
- 首轮浏览器试玩反馈：用户认为人物可再大一点、移动速度可用，攻击表现不自然。v0.2 先将人物显示比例增加约 20%（待机本体约等效 44 源像素），保留移动速度；通过身体发力、双手配合、各段挥刀轨迹与收势改善空挥。该调整尚待用户复评，不视为真机验收通过。
- 使用统一脚底锚点，以地面位置决定碰撞、纵深与 Y 排序；视觉特效不直接充当命中范围。
- 像素素材采用最近邻采样，优先整数倍显示；必要时留边，宽屏可扩展背景。适配不能改变移动与攻击的空间规则。
- 战斗画布、UI 逻辑布局与设备实际渲染分辨率分别处理；不将整屏文字压成 480×270。
- 逻辑位置保持连续；显示像素对齐方式以不产生明显移动抖动为检查项。完整帧框、帧数和动画帧率仍为可调整样板参数。

## 4. 移动与触控

### 4.1 左侧摇杆

左下固定底座虚拟摇杆，支持任意输入方向。移动不采用四方向锁定，也不对最终斜向速度作统一归一化。

- X 轴：根据摇杆横向分量大小变速，轻推慢走，推到底跑；横向死区内不移动。
- Y 轴：纵向分量越过死区后，以固定速度向上或向下移动；该速度不随力度及横向走跑状态变化。
- 斜向同时应用两轴分量。对合成速度归一化会改变固定 Y 轴速度，因此不采用。
- Y 轴速度独立于 X 轴最大速度配置；具体速度、死区、横向曲线在原型中调试，不视为已确认数值。
- “Y 轴固定”描述自由移动输入规则；出招锁定、受击、击退、突进和场地边界可按相应状态限制或替代移动。

### 4.2 朝向与按钮

- 横向输入改变左右朝向；纯纵向移动保留原朝向。人物先使用左右朝向，不要求八方向动画。
- 右下大普攻键，四个小技能按钮排在其上方；触控布局在 H5 重新构建后需按 Note20 Ultra 双手握持复测间距和遮挡。
- 支持移动与攻击/技能同时触摸；松手、触摸取消时释放对应输入，不能出现卡键。
- 按钮均应在安全区内；实际尺寸与间距按 Note20 Ultra 正常双手握持调整。

### 4.3 角色动作参考规范

用户指定以其描述的 **Codex 宠物交互表现**作为动作设计参考：拖动宠物时，可看到左右移动、站立、转向、跑跳及动作切换。这里记录的是用户提供的参考描述，尚未检查该宠物的实际代码、素材或技能实现。

原型需体现以下表现要求：

- 待机时有可辨识的站立动作；开始移动、改变方向、走跑切换及停止时，动画与角色状态一致，不能只平移一张静止图片。
- 左右运动时正确更新朝向；纯纵向移动继续遵守保留朝向的规则。停下后保留最后朝向。
- 横向慢走与跑动有可辨识的姿态或节奏差异，动画步频与实际速度协调，避免明显滑步；纵向仍按已确认固定速度移动，不因动画切换改变速度。
- 起步、停步及转向切换自然且响应及时，不能为等待动画结束而额外拖延摇杆响应；攻击与受击仍遵守各自状态限制。
- 跑跳作为身体起伏、重心和动作衔接的参考。当前原型仍无主动跳跃按钮、平台跳跃或空中连招；动画中的视觉起伏不改变脚底地面位置、纵深、碰撞或受击资格。若要增加真实跳跃机制，另行确认范围。

可复用的设计组织方式是“输入意图 → 运动/战斗状态 → 朝向与动画表现”，输入源保持可替换；游戏使用虚拟摇杆，不引入拖动角色或宠物自主游走。具体状态优先级和动画过渡参数在实现时细化。

若后续发现可访问的宠物逻辑、skill 或资源，先检查适用范围、接口、运行环境和许可，再判断是否可复用；本条不声明已经取得这些资源，也不将宠物 skill 作为 Cocos 游戏运行依赖。无法直接复用时，在 Cocos 中实现同类动作表现即可。

## 5. 动作与对抗

- 三段普攻：交叉斩→反手上挑→下劈收势，基础280/300/420ms（总1000ms）；攻速1/1.25/1.5×按当前段锁定，下一段采用新倍率。详见[攻速与取消](combat-attack-speed.md)。
- 单击只请求一段，末120ms最多缓存一次续招；动作结束后300ms内点按接下一段，超时从A重启。按住连续循环，松手不再生成续招；明确点按形成的缓存保留一次。
- 成功施放技能立即取消普攻并清空按住和缓存；失败的技能输入不影响普攻。受击打断重置连段。
- 十字斩近身与发射2段，崩山击3段且终段击倒，拔刀斩1段，大崩拍地与地面爆发共4段；具体时间与控制见[命中反馈规格](art/motion-studies/warrior/skill-hit-feedback.md)。每目标每段只命中一次，已发射十字和已落地的大崩残留按各自生命周期继续。
- 每次有效技能命中刷新5秒流血，不叠层；临时每秒0.2点、间隔不因刷新重置。DOT可致死，有跳字，无僵直、火花、击退和顿帧。数值待正式平衡。
- 大崩默认前跳64源像素，起手按前超过死区时100，中途释放不改变本次距离；地面效果绑定实际落点。持续按普攻且无方向输入，每段极轻微前移1.2源像素。有方向时不叠加。
- 横向慢走/跑动、急停、受击和落地使用独立身体姿势；视觉动作不改变碰撞规则。命中顿帧、火花、跳字与落地震动已接入，UI不随地面震动。
- 出刀前段限制移动，后摇恢复；攻击有效阶段锁定面向。技能消耗法力并有独立冷却，当前数值、范围与时长仍为本地调试值。
- 怪物先预警再承诺攻击，不持续追踪；玩家有短暂受击保护。普通/精英按单次技能累计伤害阈值倒地，Boss按类型配置，详见[通用受击规则](combat-hit-rules.md)。
- 本地闭环：准备→手动开始→胜利/战败→手动再挑战。结果不自动清除，重开清除输入、冷却、技能、流血与旧反馈并恢复血蓝，保留攻速调试档。没有奖励、装备或在线资产结算。

历史四段普攻与单段技能说明已由上述实现及独立规格覆盖，不再作为当前验收条件。

## 6. 验收场景

当前构建的执行证据见[集成验收记录](reviews/h5-integration-review-v1.md)，下表按各自设备和条件验收，不以桌面检查替代真机。

### 浏览器与手机试验记录（2026-10-15）

- 已验证：预览能显示房间、战士和怪物；一次空格输入能挥刀并扣除怪物生命；拖动左摇杆能横向跑动；出现红色锁定区域后跑出区域，攻击落空且玩家未扣血。当前单怪近战循环有可读的预警和闪避反馈。
- 手机观察：用户确认手机浏览器可打开并操作 Web Mobile H5；当前人物与动作表现仍较差，尚未达到基本手感验收。该结果来自手机浏览器，不是微信小游戏包，也没有记录 FPS 或完成 10 分钟稳定性测试。
- 未验证：本轮改版的双刀普攻动作、里鬼节奏参考适配、300ms 边界、受击僵直/击退的主观手感、三怪压力和四技能视觉/命中。浏览器控制台未见错误或警告。
- Cocos 编辑器预览曾显示旧页面，不能用它代表 Web Mobile H5；手机 H5 已单独确认可运行。最新技能组需重新构建 Web Mobile 并做专项验收。

出现问题时优先调整移动曲线、人物比例、动作时序、攻击范围、反馈和布局，再重复对应场景。用户确认基本手感后，才以结论指导内容和在线基础闭环。

## 7. 验收边界与待调项

已确认的是上述 60 FPS 目标、连续测试和可感知验收条件。此前讨论过的六怪压力、P95 帧时间阈值、输入延迟阈值、多人评分等未纳入最终确认范围，不作为本次硬性门槛。

包体与启动时间应在首次样板构建时测量记录；本轮未确认数值上限，不沿用旧蓝图数字，不宣称已满足平台限制。动作原型通过不代表正式发布性能已通过，其他设备覆盖与发布门槛后续单列。

调试项包括两轴速度、死区、横向变速曲线、按钮尺寸、人物比例、双刀普攻动作与节奏、动画帧框/帧数、攻击前后摇、输入缓冲、取消与衔接规则、约 300ms 的连段窗口、受击保护时长及四技能数值。连段计时起点及受击打断/释放技能重置连段已确认；技能动作、单次判定与覆盖范围仍需真机复评。调试结果需留记录，不能把建议初值写成用户已确认结论。

## 8. 实施边界与交付证据
