# 访问路径、索引与事务设计 v2

更新：2026-10-20。状态：E03工程提案，待收敛及eng-review；未创建索引、安装SDK、运行数据库实验或修改代码。依据：[数据字典](data-dictionary-v2.md)、[核心契约](core-contract-v2.md)、[模块依赖](logical-architecture-v2.md)、[挑战流程](../challenge-flow.md)。

本稿确定逻辑访问与一致性要求，不臆定CloudBase版本的事务/索引/字节上限。物理能力须在E07核对官方文档及目标环境验证，验证不通过就调整模型或禁用内容，不带着未证明的原子性开工。

## 1. 物理映射候选与查询原则

建议独立承载身份、账号、会话、钱包、角色、容器、装备、邮件、永久/其他交付来源、挑战、房间、操作结果、流水、配置发布/指针和排行投影。首版不把这些变成独立服务。

- 常见资产命令用确定主键读取；不在事务里全表搜索纹章、钱包或角色物品。
- 槽位最多100、装备穿戴最多13，可读取有限容器后在内存计算兼容堆叠与空格；不能为省一次固定文档读取而额外建无可靠维护的库存计数。
- 各实体归属从服务端受信身份解析；即使按ID查询，也验证accountId、characterId及当前会话。
- 邮件/待领/历史流水等无界历史必须分页；不能把全量列表放账号文档或一次事务。
- 随机地面描述及逐怪收益留在有限房间账目；装备成功拾取后物化。通关专属待领装备与grant保持一致，不能每条地面描述提前造完整装备实例。

## 2. 查询与索引候选

索引中字段顺序为逻辑前缀/排序需求，不声称目标数据库按此语法可直接建成；需要验证等值过滤、范围与排序组合和扫描量。

| ID | 访问路径 | 过滤与排序／已知主键 | 索引候选与一致性要求 |
| --- | --- | --- | --- |
| Q01 | 登录身份→账号 | H(platform,appId,subject) | 主键查；不存在时事务同键占位，禁止扫描subject |
| Q02 | 当前账号/会话/钱包 | 受信accountId、sessionId | 主键查；epoch和账号写栅栏保护修改 |
| Q03 | 当前角色/三类容器 | account职业映射、角色固定containerId、账号vaultId | 主键查；各类容器归属分别验 |
| Q04 | 穿戴/拖动目标实例 | 最多13个穿戴itemId或当前槽itemId | 有界按ID读取，数量/字节限制；不开放任意批量私有ID查询 |
| Q05 | 邮件倒序列表 | accountId+characterId+status，createdAt DESC,id DESC | 复合索引候选；按稳定游标分页，禁止offset越翻越慢 |
| Q06 | 邮件未读提醒 | 当前角色active且readAt缺省，时效需校验 | 候选读投影或有限存在性查询；计数不是领取权威，不因提醒过期拒奖 |
| Q07 | 永久待领倒序列表 | accountId+characterId+route=pending+state=available，createdAt DESC,id DESC | 复合索引；无自动过期和导致拒收的数量硬上限 |
| Q08 | 邮件/附件/grant详情与领取 | mailId/attachmentId/grantId | 已知ID；事务内重读时效/交付状态，列表不是授权凭据 |
| Q09 | 当前挑战/房间/操作原结果 | account指针、H(challengeId,roomNo)、H(accountId,operationId) | 主键查；业务去重包含零扣费房间，授权后查原结果 |
| Q10 | 超时挑战候选扫描 | result=active且leaseUntil到期；另查looting超时 | 分开候选索引；事务内重读mode/epoch/deadline/result，不按扫描快照直接终止 |
| Q11 | 账号流水 | accountId，occurredAt DESC,id DESC；按sourceId追踪 | 时间索引+来源索引候选，限定时间/页大小，管理员权限与玩家视图区分 |
| Q12 | 排行总榜/职业榜 | score DESC,scoreReachedAt ASC,characterId ASC；职业榜先classId | 总榜/职业两索引；相同时间ID稳定决胜，不暴露私有库/钱包 |
| Q13 | 已发布配置 | releaseId／H(environment,profileId) | 指针主键查后按不可变引用加载；测试授权不交给客户端布尔值 |
| Q14 | 投影待处理候选 | status+nextAttemptAt ASC,id ASC | 采用异步时才需要持久工作记录；重复处理按版本幂等 |

### 邮件到期与稳定分页

邮件UI可见性需排除到期，但不能假定createdAt排序索引同时廉价支持任意expiresAt范围。提案采用status候选索引＋服务端时间检查＋有界补页扫描，后台将过期项逻辑终结；游标推进到最后已扫描项，不只最后返回项，避免死循环。每页有响应条数、扫描条数和字节预算；预算耗尽返回游标/未扫描完标记，不宣称没有更多数据。具体索引与扫描阈值待E07验证后定。

新增邮件不回插旧游标之后的排序位置：继续翻页可忽略之后生成的新项，刷新首屏再看新邮件；同一createdAt以id稳定排序。跨页领取导致条目消失时，不用offset导致跳项或重复发奖，领取仍按来源状态去重。

### 统计提醒、排行与隐私

未读/待领数量若缓存，只能作提醒；需可重建、版本防倒退。排行榜已确认非实时、按需懒加载；同分按实际最近达到时间，分数不变保留，回到旧分重新计时。具体刷新/缓存时效待工程设计，不把查询时间当分数变化时间，也不承诺实时名次。UI新增他人完整装备检视需要独立公开字段与授权设计，当前不默认开放Q04私有实例查询。

## 3. 事务共同骨架与计数方法

正常已登录写操作共同读取账号A、会话S、原操作O（包括不存在的已知键），写A的writeRevision和O结果。下表以`R0=3`、`W0=2`示意基础数；不含额外角色选择权限读取、到期处理、配置读取或SDK额外行为。首次登录/接管单独计算，不能机械套R0。

定义：`R=|唯一读取键集合|`，`W=|唯一写入键集合|`，并另记录SDK实际调用次数、读取/写入字节、单文档上界及重试成本。一个键读写都计入其对应集合；若SDK按调用数而非唯一文档限额，需要以实际规则重新预算，不能用本式冒充平台限制。

`J`为本次有界账本条数，`G`为实际交付来源记录数，`E`为受影响实例数，`M`为新增节点邮件数，`C`为事务中需读取的配置/授权引用数。配置缓存仅限不可变内容，权限/价格激活指针如需要强一致校验仍要计读。

所有确定性主键的“不存在检查”、版本检查、同源并发占位也纳入预算；不能只数成功写入。日志投递不是业务事务的一部分，但原结果/关键账本是。

### 可复算的三个示例

1. 银行单装备转移，若A/S/O外仅读角色、两容器和1实例：R=3+1+2+1=7，W=2+2+1+J=5+J。若需校验额外服务许可/配置，还要加其读取；UI拖动不让服务端省略校验。
2. 单阶段个人库解锁：除A/S/O外读角色、容器、钱包及C个配置引用，R=6+C；写容器、钱包及J，W=4+J。另一币种并发需重读stage/钱包，不能只在客户端防双击。
3. 全修：R=3+角色1+钱包1+E+C=5+E+C（0≤E≤7，实际若为判断无需修理而读取7件，也按7计）；W=2+钱包1+修理实例E+属性/评分附加键K+J。E和K按实际读写集合计，不把同一角色重复算作两个写键。

以上不是SDK最大允许数，更不是实测结果。真实平台预算由用例对象数、配置导致的M/G/J/E变化、序列化字节及事务重试一起决定。

## 5. 终局、升级与批量的最坏预算

### 房间事件与终局

为每个副本配置计算：N=房内怪数（含紫名），D=所有怪/首领及通关产生的最大条目，M=一次奖励可能跨越的等级邮件节点数，E=同笔磨损装备数≤7，G/J为交付/账本条数。普通首本当前N≤7，整局28；其他内容尚待定，不能用这个N替代通用上限。

最坏事件事务需要同时覆盖：房间全部未结算收益、角色升级、钱包、最多7耐久实例、所有跨级节点邮件来源、通关装备与满包待领、免费复活/难度解锁及操作结果。必须在发布前计算唯一键数和序列化字节。因经验过大可跨多个节点，不能只测“升1级”预算。

若预算不满足：优先减少不必要物理来源记录、合并同笔有界账本、调整内容发布的合法上界，或提出完整的持久交付协议重新评审；不得战斗时临时拆成先通关后尽力补奖励，也不能为满足预算私自削减用户已确认奖励。

### 一键邮件领取与大列表

一键领取是有界编排，按稳定附件键逐项或有限批执行，返回逐项结果/剩余游标。每个附件交付与入包原子，前几项成功后后项满包可停，符合“尽可能领取”。UI关闭/网络未知后查询已有各来源结果，不重领前项。

不得用一个无法恢复的客户端循环代替服务器交付凭据。单个堆叠附件可按可容纳数量部分领取，装备按整件；每笔记录实际交付量与剩余，不因重试再扣一份。永久待领与邮件列表无数量硬上限，但单次响应/事务必须有界。

## 6. 竞态、随机与失败恢复

| 竞态/故障 | 确定处理 |
| --- | --- |
| 同账号两服务写/页签切换 | 共同A栅栏+目标版本；迟到结果只更新其对象，不覆盖当前页签 |
| 同装备转移/强化/出售/穿戴 | 位置与版本竞争，只一笔有效；永久实例与槽/穿戴同改 |
| 新旧会话接管 | 同账号写冲突，旧epoch重试失权；先提交的合法收益保留 |
| 同房不同ID、到0跨刷新 | 查已处理room，保持快照；不重复扣零或从新窗口扣 |
| 回城响应丢失+新挑战后旧请求重放 | 查结算来源，返回旧结果不覆当前体力/location；展示另读最新状态 |
| 邮件到期与领取 | 每次事务重试重取now；有效提交时间到期则拒绝并保留过期凭据，不按客户端点击时刻追溯 |
| 首领/残留/付费复活与截止 | 沿生命周期合法事件和首个有效事务决定，不能用旧simulationTick改判；不新增自动退纹章 |
| 随机候选与自动事务重试 | 同调用候选稳定；查业务来源首个结果，失败候选不显示为真实奖励 |
| 提交成功丢响应 | unknown，查原O；notFound仍可能在途，沿原ID/原参数重试，不生成新意图 |
| 投影/提示失败 | 资产成功不回滚；若采用异步，须持久待办与版本重建，不依赖内存事件 |

事务内不做外部HTTP/平台身份交换/资源上传或不稳定随机调用。报价/内容切换需有配置引用和重验逻辑；平台Adapter若自动回调重试要保证纯决定与候选数据不变化。

## 7. 扫描、归档与服务访问未决

超时扫描仅找候选，事务内重读截止和会话版本；邮件到期可删正文但保留来源状态，永久待领不套邮件TTL。operations/grants/流水的保存策略需E06定稿，在此之前不得自动清去重键。

仅银行/邮箱/NPC附近可服务的规则已确认，但目前无可信城镇运动验证。E04/E07需设计服务访问上下文或等价机制，并明确其证明能力，不能声称客户端上报坐标/`nearNpc`即已防伪。UI稿中新加城镇可见其他玩家、完整检视、好友/私聊等不在现有后端授权/索引范围，需先处理范围审阅。

## 8. 评审与验证出口

官方资料核对已汇总到[E07平台提案](platform-security-operations-v1.md)，所载限制不等于目标SDK操作计数/事务预算已实测；仍须按每个用例重新验证，不将本稿符号读写数直接等同SDK“操作数”。

E03设计检查材料：每个T用例对应Q访问、实际键列表/字段体积、最坏内容配置、所有失败与并发路径。后续目标平台验证至少包括确定ID并发占位、共同A冲突、回调重试、缺失读取、事务原子性、读写/字节限制、复合排序/游标、权限拒绝及配置缓存一致性。

本轮只产出方案和符号预算，不执行测试、不声明数据库能力已证实。下一步E04完整协议/状态整合，同时E06配置发布/迁移和E07平台假设补齐；产品数值/范围未决继续按完整性审计关闭。仍须完整方案收敛→eng-review→问题关闭→coding。
