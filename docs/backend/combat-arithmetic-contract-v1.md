# 战斗数值精度与事件顺序合同 v1

日期：2026-10-21。工程候选，未正式eng-review、未实现或执行确定性测试。不调整武器公式、Boss数值或既定玩法。承接[时间基线](simulation-timing-and-budget-v1.md)与[检查点](simulation-checkpoint-schema-v1.md)。

## 表达与运算入口

位置采用既有候选每设计像素1000整数单位；时间配置为整数微秒或约分有理数，持久逻辑游标仍为10ms步。HP、MP及伤害内部候选每单位1000整数精度，UI显示取整不回写权威值。概率采用整数分子/分母；急速、减伤和倍率先组合为有理数，不经过客户端显示小数。

共享规则层只暴露版本化运算入口：mulDiv、allocateBudget、mapEventTime、compareDistance和serializeState。中间乘积使用精确整数运算；跨JSON边界以十进制整数字符串编码超出安全整数的值，禁止直接JSON序列化BigInt。平台适配器不得自行改舍入方法。最大坐标、倍率、作用目标和累计值在配置发布时校验，超界拒绝配置，不在战斗中截断伤害。

非负资源扣除和伤害写入最小单位时向下取整；负数不隐式套用此规则。HP/MP限制在当前合法最大值内，扣药效果与扣库存同一权威事件。伤害最小值是否为0或另有既定下限由数值配置提供，本合同不新增保底1伤害。

## 多段与时间映射

每次施放先冻结攻击端快照及技能原始总预算，按固定权重分配各段：前段向下取整，最后一段承接余数，保证各段原始预算和等于整次预算。不同目标、不同命中/暴击结果不共享最终减伤余数；未命中的段不将伤害补给后段。流血只分配原本固定跳数，不因急速/切片补造跳数。

每个事件时刻从施放原点独立计算：origin + offset / haste，再映射到不早于原始时刻的首个逻辑步。禁止逐段累加已取整间隔。相同节点即使落同一步仍分别执行，保留原始有理时刻及稳定节点序号用于排序。冷却到期同样从施放原点计算；急速后续变化不改旧快照。墙钟死亡/恢复截止继续使用服务端Time，不转换成可暂停的战斗tick。

## 同步与同刻事件

输入先经sceneEpoch/timelineEpoch、序号和已接受时间前沿校验；逻辑事件排序键候选为逻辑步、原始时刻、事件类别、创建序号、目标稳定ID。目标遍历不依赖容器枚举顺序。到期的墙钟截止先于接受新片段判断，不能通过片段内排序续命。

同一逻辑步内按原始时刻推进，属性变化在各自事件后对后续节点生效；旧攻击端快照保留，目标护甲/减伤按节点实时读取。单个伤害节点原子完成命中、直接伤害与合法控制/附着，再处理对应死亡、XP与升级。Boss死亡处理通关和间接击杀收益，之后末房磨损；玩家已死时按既定规则免费复活。已释放残留保留，死亡不得批量删除它们。

完全同原始时刻采用固定候选分层：到期状态→已提交输入中的合法消耗品效果→已生成伤害节点→玩家死亡及其磨损→敌人死亡（首领通关优先处理间接击杀）/XP/升级/免费复活→仍活着者的新动作起手。伤害节点以该时刻开始时的合法释放/存续集合执行，控制取消严格后续时刻的未生成节点，不凭遍历顺序删除同刻既有节点。先处理玩家死亡再认定首领通关，与API/状态表已有顺序一致；已有残留与直接攻击仍依来源区分。该层次是具体待审工程候选，并非已通过确定性验证。

## 检查点与验收出口

检查点必须保存整数资源、未触发节点原始时刻/序号、施放快照、分段预算与余数、独立随机流游标和规则版本；只保存屏幕浮点坐标不足以恢复。规范化编码固定字段、集合稳定排序；状态摘要不包含渲染插值、日志时间或资产私有随机种子。

实现后必须验证：任意片段切法与30/60/120渲染帧下同输入同结果；1倍/2倍及非整除急速下预算/跳数守恒；0伤害、擦边、最大坐标与乘积；中途升级/破损/增益变化；末跳击杀Boss、玩家先死及完全同刻；检查点编码往返与随机游标重放一致。上述是待执行验收，未新增试算或测试通过记录。

加载/切房握手、并发效果与编码上界、具体SDK/runtime兼容性仍由后续合同收敛，本稿不以整数方案代替这些缺口。
