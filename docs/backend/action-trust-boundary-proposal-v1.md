# 地点与战斗动作可信边界提案 v1

日期：2026-10-21。状态：用户已确认选择A服务端可验证行为，具体协议与预算待eng-review；不授权编码或建云资源。依据[平台方案](platform-security-operations-v1.md)、[API](api-contract-v2.md)、[挑战流程](../challenge-flow.md)。

## 1. 必须分开的三种保证

1. 身份与资产：真实账号、物品归属、一次消费和一次发奖由服务端验证。
2. 行为规则：动作时序、冷却、资源、状态和地点许可由服务端可重算的数据验证。
3. 战斗事实：是否真实移动、碰撞、命中、受伤。若事实仍由客户端报告，则前两项正确也不能证明第三项真实。

本提案不引入实时多人或常驻逐帧服务。仅提交最终HP、ready、击杀数或客户端签名不能解决第三项；客户端可得的密钥不能成为可信证明。

## 2. 推荐候选：有序输入与服务端可验证状态

客户端即时表现，按挑战/房间的连续序号提交有界输入片段；服务端保存已接受游标和规则快照，在消费、结算和检查点前重算。状态至少覆盖：生命/魔法及最大值、玩家生死/控制、职业技能与药品/饰品CD、装备/临时增益、已确认事件与残留段、怪物状态、确定随机来源和必要位置。

输入记录应包括移动意图变化、普攻/技能/药品/饰品意图以及服务端控制事件引用；受伤、击杀与客户端HP是校验对象而不是独立权威命令。输入序号不等于可信时间：服务端校验片段时间跨度、累计模拟时长与有效在线/暂停状态，拒绝倒退、越过未确认间隔及异常超速。

要证明命中/受伤，必须有可重放的怪物行为、碰撞/位移和随机选择；只重算蓝量与CD仍属部分校验。共享纯规则需要固定时间步、取整、命中窗口、目标顺序和随机种子使用；不能在客户端用动画帧、服务端用另一套时间定义。当前纯函数和试算不证明完整可重放战斗已经存在，此处是成本明显的设计候选。

## 3. 药品与饰品原子边界

应用先恢复到操作前已验证游标，再检查生死、满值拒绝、资源/CD、背包数量或装备资格。合法药品消费须与恢复效果、共享CD及动作游标一起提交；饰品效果与独立固定CD一起提交。客户端未获确认前的预测不能用于后续权威发奖。

若重算超预算，不得先扣药后再补状态，也不能先接受客户端HP绕过。应拒绝尚未执行的新操作或进入明确恢复状态，保存最后已确认游标和原结果。已经提交的操作仍查询原结果，不以重算超时重抽或重复扣药。

## 4. 两类时间

战斗推进采用已接受模拟时间，断网/后台暂停不能暗中消耗战斗CD；恢复/死亡截止等沿生命周期的服务端墙钟规则。两者显式记录，不能用客户端毫秒或请求到达时间统一替代。暂停后提交的动作只能覆盖合法暂停前片段；恢复后不能补写原本不该发生的战斗。

## 5. 城镇地点

同样区分两档：仅校验“当前在城镇且锚点合法”可阻止副本内远程银行，但不能证明步行；若本期要求可验证步行，应基于服务端当前地点版本、合法出生点、移动输入/可通行路径与速度上界验证进入交互范围，再签发对应服务上下文。操作时重验地点版本/角色代次，离开或切角色使上下文失效。

全套地图路径与碰撞校验需独立预算；只有直线距离/最短耗时不足以证明绕障碍步行。不能偷偷把NPC要求降成任意城镇位置可操作，也不能把客户端点击NPC当作可信证明。

## 6. 有限候选与取舍

| 方案 | 能保证 | 局限与成本 |
| --- | --- | --- |
| A：有序行为账本，关键战斗/地点可重算（推荐作为正式目标） | 除资产一致性外，验证所覆盖的移动、动作与战斗事实 | 需要确定性规则/碰撞/AI与分段成本设计；环境、复算成本及实际覆盖仍须验证 |
| B：内测弱校验 | 身份、资产、防重、manifest/事件预算和部分动作合法性 | 客户端命中/受伤与地点仍可伪造；仅限明确标记的隔离内测，不能宣称正式经济已安全 |

选择A不表示已证明抗所有作弊，尤其客户端可辅助操作仍需另审；选择B需要明确接受上述测试限制，不能默认升级正式上线。2026-10-21用户已选择A作为本期在线闭环设计方向；B保留为已比较的替代项，不作为本期降级路径。方向确认不代表确定性、平台能力和成本已验证。
