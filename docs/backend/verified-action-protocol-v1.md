# 可验证动作输入与检查点协议 v1

日期：2026-10-21。状态：用户已选择服务端可验证行为方向；以下字段与执行流程是工程提案，待eng-review、预算与确定性验证，尚未实现。依据[可信边界](action-trust-boundary-proposal-v1.md)、[API](api-contract-v2.md)、[生命周期](state-transitions-v2.md)。

## 1. 职责与验证范围

客户端即时输入、预测和动画表现；服务端按有序输入重算移动/碰撞、怪物行为、命中受伤、生命魔法、控制/残留、职业技能及药品/饰品效果与CD，再确认收益与资产。只校验资源/CD但仍信任客户端击杀的实现不满足本方向。重算成本与精度未验证前不能称已具备可靠反作弊。

不引入实时多人战斗或常驻逐帧服务器；共享规则是无Cocos依赖的确定性内核，渲染可不同，判定规则与时间定义不得不同。现有客户端模型与试算脚本只是迁移输入，不自动成为可重放内核。

## 2. 输入片段候选

| 字段 | 约束 |
| --- | --- |
| operationId、会话与rolePlayEpoch | 可信身份另由Adapter解析；请求身份不替代归属/当前代次校验 |
| challengeId、roomNo、sceneEpoch、timelineEpoch | 绑定当前合法场景及输入时间锚点；短恢复只递增timelineEpoch，不使原场景地面掉落失效；城镇使用独立地点场景版本 |
| baseCheckpointVersion、firstSeq、lastSeq | 从已接受检查点连续推进，不跳序、不将同序不同内容覆盖 |
| fromTick、toTick、规则/地图引用 | 沿已接受模拟时间连续，步长、速度与可接受跨度由版本配置定义；数值待验证 |
| inputs | 有界移动意图变化、普攻/技能/药品/饰品意图；校验枚举、数量及触点归属后的动作，不接收任意函数/脚本 |
| digest | 服务端规范编码后核对重放一致性；摘要不是证明客户端诚实的签名 |

客户端HP/怪物死亡/命中列表可作差异诊断，但不是奖励或消费授权。装备变动、药品资产版本、复活和服务端生命周期事件需作为有序的外部事件引用进入模拟，不能在当前穿戴已改变后用新属性重放旧技能。

## 3. 检查点与重放

检查点保存场景与规则版本、输入游标、模拟时钟、玩家/怪物位置与状态、资源/CD、控制与流血/残留段、随机游标及必要装备快照。大小由配置上界约束，不能无限追加日志到同一文档。服务端选择合法随机来源并验证消耗顺序；是否将种子公开给客户端、预测信息暴露与操作辅助风险需安全复核，不把私有掉落随机源下发作战斗预测。

同一输入与规则从同一检查点应得到相同判定结果；固定步长、取整、目标排序、碰撞边界及浮点差异必须有版本契约。输入历史按有界片段保存，归档与清理不能删除未知提交恢复、审计及必要重放证据；具体期限待迁移/运维方案。

## 4. 执行与原子提交

1. 校验身份、当前代次、片段大小及原operation；原结果重放不再模拟和消费。
2. 读取已确认检查点及引用版本；有界重算候选结果。重算可以在事务外执行，但不能在这里改权威资产。
3. 单个提交事务重验检查点版本、会话/代次栅栏、生命周期截止、相关装备/资产版本；候选结果仍适用才一次提交新游标、状态、消费/收益来源与原结果。冲突后丢弃旧候选，按合法最新基线恢复，不盲目重用。
4. 药品数量、效果和共享CD，饰品效果和独立CD，与对应动作游标同笔成功或失败；片段内升级、武器归零等事件沿既定顺序。
5. 超时未知查询原操作；未验证输入不产生可领取奖励。客户端依确认检查点纠正预测，表现平滑方案不改变服务端结果。

重算不得长时间占用数据库事务等待动画/网络。是否允许片段内多个资产动作及分段上界须以最坏预算验证；不因超限把扣费和发奖拆成不完整两笔。缺片段时返回期望序号/检查点引用，不能悄悄丢输入后继续确认击杀。

## 5. 时间与恢复

模拟时长受服务端接受的有效活动时间、版本化容差与暂停状态约束；客户端自报tick、请求间隔或包内时间均不能独立证明真实经过时间。首次挑战/房间、暂停、恢复、死亡/复活等边界需保存服务端时间锚点，防预提交、加速与暂停后补战斗。

战斗CD使用模拟时间；死亡/重连等截止沿服务端墙钟。具体10秒窗口及免费复活等沿生命周期，不能因验证延迟重设期限。输入在暂停前生成、暂停后到达等竞态需明确可接受边界和证据；没有证据时不信客户端时间补写。确认资产保留、未确认预测纠正；不新增任意回档或补偿规则。

## 6. 城镇验证

从合法出生点/返城门口检查点接受移动输入，验证可通行路径、速度和NPC范围，再签发绑定地点版本的服务上下文。服务操作时重验位置、角色代次及锚点；客户端说“已到银行”不能单独授权。城镇无战斗模拟，但路径/碰撞与输入预算仍需验证。

## 7. 准入证据与未决参数

- 跨客户端/服务端确定性：同输入同随机游标、不同帧率和执行分段结果一致。
- 负面场景：假击杀/HP、超速、跳序、同序异参、旧代次、过期场景、暂停补写、药品满值/不足、饰品CD伪造。
- 原子性：消费、效果、游标和原结果同成同败，重试不重复，切角色/死亡/终局并发不绕过。
- 最坏性能：单段CPU、检查点字节、SDK读写/冲突、带宽与费用；记录机器/SDK/配置，不能用离线试算次数代替。

固定tick、批次时长、同步频率、时间容差、检查点周期、日志期限、预测纠正、随机可见性和异常恢复仍需方案。方向已确认不等于这些工程细节已冻结，也不代表G03/V06通过。本轮没有编写或运行验证代码。

当前时间与恢复候选统一见[恢复时序第6节](recovery-timeline-proposal-v1.md#6-统一时序候选本轮方案收敛待用户许可后再eng-review)：单段1秒、2秒连续输入缺口、最多1秒未确认预测均为工程候选；10秒恢复/死亡规则不变。resume与旧输入以检查点版本争用，成功后重建时间锚点、递增timelineEpoch，acceptedSeq/Tick不清零。新输入须同时匹配当前锚点代次，不用sceneEpoch承担两种含义。正式eng-review须另经用户确认，本轮只有方案收敛。


时间、确定性与费用候选见[模拟时间与预算基线](simulation-timing-and-budget-v1.md)，含候选参数、累计时间防加速、断线证据限制及10分钟调用量算式。未实测，不将候选视为配置已冻结。

## 恢复体验最新确认（2026-10-21）

用户明确战斗表现不要求强一致，允许秒级回溯；短恢复先查询原请求结果，再以服务端最新确认检查点恢复，未确认移动/攻击表现允许修正。这不放松钱包、消费、发奖与原操作结果的原子性，已确认资产和收益不撤销。

持续无法恢复时显示「网络中断，请重新进入游戏」，停止继续战斗并要求重新进入；沿用既有10秒恢复窗口，不另增宽限或自动续关。未通关超时失败/关闭并保留已保存收益，已通关仅关闭拾取场景、不撤成功；新launch默认旅店，不重启续关。客户端提示不单独改服务端结果，下一请求/清理仍按原持久截止处理。

此前为减少修正提出的持久输入收据不作为本期必需方案；采用原操作结果和权威检查点恢复。秒级是体验尺度，不保证任何弱网都只退1秒；必须限制未确认预测积压，超上界先暂停等待，不允许无限本地刷怪或离线补报。具体积压上界和时间锚点待工程验证。
## 动作拒绝与片段失败的工程语义候选

结构、身份/代次、连续序号、版本、时间前沿或配置错误属于整片段失败：不写检查点或资产；返回期望游标/恢复引用，不暗中接受片段尾部。原请求提交未知先查原结果，不能一边重算一边更换同ID参数。

满蓝用蓝药、技能CD中按键、未解锁技能等可由正常玩家输入产生，属于顺序中的动作未执行：记录有界拒绝原因，动作无效果/无消耗，后续合法移动输入继续模拟。该输入序号已被处理，不当缺包反复重试；可按配置将高频重复拒绝原因合并展示，但不能删除计数和吞合法动作。恶意超量输入仍按速率/片段预算拒绝，不能借此制造无限CPU。

合法技能才可触发普攻取消，低蓝/CD/未解锁拒绝不取消当前普攻。药品满值拒绝不启动共享CD。片段中成功与合法动作拒绝的所有最终决定，与检查点、资产和原结果一次提交；若提交事务失败，先前模拟得到的局部成功都不是已提交事实。

服务端语义拒绝不能被客户端自行改成成功，也不意味着每按一次技能就新增独立数据库操作；输入序号用于顺序，operationId用于提交片段/外部命令防重，作用不同。该候选语义需在eng-review检查与既有输入/缓冲规则的一致性，尚无实现测试。
