# 战士场景并发与编码包络 v1

2026-10-21。供设计评审的应用约束候选，不是平台已测上限；不修改游戏配置。本包络只覆盖当前战士三本候选，不支持猎人/召唤/无限递归效果自动落入本基线。

## 配置发布约束与导出上界

当前候选每房最多8个敌人、单玩家；无召唤/分裂再生，7房，至多56个击杀来源。玩家每技能单施放最多4直接节点，每节点每目标最多命中一次、最多附着1份流血。每份流血最多5跳、最长5逻辑秒；从施放到最后直接节点最长4秒；独立投射物/地面效果最长9秒。实际技能可以更少，不能运行时达到上限后丢效果。

候选最低相邻起手间隔120ms（已含2倍急速及取消衔接），来源必须经行动状态机，不能通过移动/取消/重连在一个时刻无限发招。怪物每个来源相邻起手最低500ms，每施放最多6个独立效果（覆盖首Boss吼叫6节点）；怪物本候选不施加可叠流血。内容编译器逐一验证实际动作/取消图，不能仅凭普通CD推导上界，因为复活会重置职业CD。若现有动作有更快合法路径，拒绝将本包络声明为适用并重新计算，不强加静默限速。

保守窗口9秒内玩家施放数≤ceil(9/0.12)+1=76；同时可能存在的逐目标流血≤76×4×8=2432；玩家脱手节点≤304；怪物独立效果≤8×(ceil(9/0.5)+1)×6=912。不同快照/跳伤随机游标分别保留，不合并伤害。最高共3648个效果记录是保守存储分配，不是必须在每步执行3648次伤害；固定事件索引调度到期项。

暂停不推进逻辑存活也不能产生新起手；死亡残留计入上述窗口。旧场景切换清理场景作用域，不能让7房累计活效果。零CD循环、自触发递归、新buff延长效果或额外节点会改变边界，必须重新发布协议包络。

## 唯一物理选择

2026-10-22正式评审决定1A（用户确认）：CP采用独立checkpointHeaders/H(challengeId)与按实际状态使用的1～8个checkpointChunks/H(challengeId,ordinal0..7)。头≤16KiB，单chunk完整UTF-8≤80KiB、最多640KiB；不用的块不预建、不每次写空块。头含revision、accepted游标/时钟、activeChunks[{ordinal,chunkRevision,hash,sceneEpoch}]，每个ordinal最多一次。

普通推进先读取当前头及全部在用块获得完整权威状态，再重算；提交事务重验头revision及读取状态版本，原子写头、实际变化/新增块和本次资产变化。未变化块保留旧chunkRevision/hash，**不要求所有块revision等于头revision**。不能缓存旧块后只验当前头而略过引用匹配。最坏仍可读写9个CP键，常态按实际在用/变化块计量。

收缩时仅从新头去掉不再使用的块引用，不在热事务逐块删除；闲置旧块不可独立查询或恢复。下次复用ordinal时写入新chunkRevision与sceneEpoch/内容摘要，与头同笔提交，禁止仅凭同ordinal或数值版本猜测可复用。切房必须初始化新场景合法状态；旧场景块只有字节内容/场景归属符合新引用才可用，不因为延迟删除而串入新房。关闭挑战后以H/头的可访问状态拒绝恢复，不依赖逐块物理清理。

恢复读取采用“头r→按其引用读取块→再次读头”：两次头revision一致，且每块sceneEpoch/chunkRevision/hash均匹配才组装；任一不符则丢弃整份读取重试，不能把合法旧块误当混版，也不能用缓存拼接。已进入恢复暂停的输入栅栏与原10秒截止仍有效，不因读取重试续期；响应丢失先查原operation。

分块布局保持稳定：优先原块更新/复用已空槽，只有容量增长才加块，不每次把所有记录重新紧密打包。时间字段用块内固定baseTick+事件偏移/绝对到期刻，头acceptedTick变化不要求给每个倒计时字段重写剩余时长；语义仍按原逻辑时间结算，不能靠存储优化改变效果时刻。实际事件或状态改变造成全块变更时如实计量，不承诺所有片段都能少写。

块内采用版本化紧凑字段数组及小整数局部引用；效果单条编码预算≤128字节（固定字段数、数值位宽、无重复长ID），施放快照≤192字节且共享只读引用。理论效果466944字节，最多228份施放快照43776字节；敌人/玩家/索引/余量约64KiB，总计576256字节（约563KiB），低于640KiB候选。该算式是字段预算分配，不是已实现序列化证明；编码器必须用最大合法值验证真实UTF-8长度及分片边界，失败则返回设计修改，不能发布后拒绝合法玩家战斗。

每块带局部schema；公共恢复视图通过授权裁剪，不能直接回传原始CP分片。片段响应≤32KiB，只包含游标、事件摘要和变更视图，完整恢复另取有界分页视图；分页需绑定revision，否则重取，不把不完整视图当可开战状态。

## 输入、ID与其他编码预算

输入片段≤1秒、最多32条规范化输入、完整请求≤16KiB；摇杆变化按逻辑步最后状态合并，离散按键不能静默丢弃，客户端提前分片。无效/越界输入整段拒绝且不扣资源、不推进游标；合法动作因CD/MP/生死不能执行则返回确定拒绝事件，片段时间照常推进。随机和资产仅在合法执行后消费。

内部物理键采用带类型前缀的SHA-256 base64url摘要（43字符）并存原元组摘要/归属；发现不匹配拒绝完整性错误。客户端operationId≤64 ASCII字符、配置引用≤64、来源局部序号整数，禁止任意长文本进入CP/J。哈希不是权限。装备每件固定基础/主/副/稀有/奖励/特殊字段槽合计≤16，重复副类型拒绝；每封系统邮件≤8附件，纪念品返还≤8，通关专属装备1件；不改变普通堆叠每堆20。

房间怪物每只最多1装备+1材料来源，金币/XP即时汇总但保留spawn来源；每房地面来源≤16。系统升级奖励每5级1封、1至30最多6封。以上为候选内容基线的合法数量，不是把已有任意奖励砍到预算。新增内容先重新算式再发布。

## 随机边界与失败出口

攻击/AI与掉落、强化随机流分离。正式服务端私有掉落/强化种子不发送客户端；预测战斗可使用独立展示结果，确认后修正，不要求公开权威随机种子实现逐帧无偏差。CP存权威战斗游标；资产结果由来源固定，在同操作事务重试中复用同抽样输入，客户端不可选择种子/operationId重抽。

发布校验覆盖整个可达技能图、最高急速/减CD/复活连续起手、8敌群、最远尾伤、最长ID、所有装备字段和跨级邮件。运行检测意外超界时不截断效果、不部分结算：整片段未提交即保留上一个确认状态并阻止继续预测，告警/查询原结果后处理；实际发布前此类合法路径必须零超界。后续技术验证失败优先调整分片/实现/配置合法域并复审，不信任客户端HP或漏奖励。


### 紧凑字段的数值域

局部actorIndex≤8、snapshotIndex≤227、nodeIndex≤5、剩余跳数≤5；效果使用相对当前步的有界剩余时长与局部来源引用，不在每行重复全局challenge/cast长ID。资源/伤害预算以非负有界64位整数十进制表示，乘积用精确更宽整数，转换回合法域之前拒绝溢出配置；输入操纵不能扩大该域。调度有理数分子/分母各≤32位正整数，配置编译后验证，不能用分母0或任意长度字符串。效果128字节/快照192字节是完整记录（含分隔/字符串引号）预算，额外来源字典/索引计入64KiB余量；适配器额外字段计入各chunk的80KiB上界。配置发布器必须对实际编码证明，纸面算式不能替代该证据。
