# 配置发布、数据迁移与回退方案 v1

更新：2026-10-20。状态：E06工程提案，待收敛与eng-review；未发布配置、执行迁移、清档或创建资源。依据：[字典](data-dictionary-v2.md)、[接口](api-contract-v2.md)、[事务预算](access-and-transactions-v2.md)、[动态掉落策略](../design/drop-strategy-proposal-v1.md)。

## 1. 配置与数据分开管理

| 对象 | 内容 | 版本/归属 |
| --- | --- | --- |
| 业务代码 | 公式实现、策略注册、验证器、协议处理 | 代码提交与构建产物版本 |
| 玩法配置 | 职业/技能、装备/词条、怪物/副本/行为、成长/经济、容器/商店、初始化和策略参数 | 不可变release及子配置摘要，测试/正式分开 |
| 公开资源配置 | 客户端表现/图集/界面和公开规则所需引用 | public manifest，兼容客户端构建 |
| 私有配置 | 服务器掉落权重、允许的策略选择、内部限额/授权 | private manifest，不随UI下载 |
| 玩家数据 | 角色、物品、容器、挑战、操作来源与流水 | schemaVersion+业务version，不被热更新整包覆盖 |

配置驱动不是下载执行任意脚本。动态选择只从当前代码已注册策略和已验证schema中解析；算法或协议结构改变仍需要代码与兼容性发布。未定价格/伤害不得藏成生产默认。

## 2. 发布清单与引用

发布清单候选字段：releaseId、schemaVersion、manifestHash、codeCompatibility、protocolRange、environmentScope、publicChildRefs、privateChildRefs、validationReportRef、createdAt、publishedAt及状态。

子配置必须显式标注字段单位/精度、合法范围、引用版本和最大数量。引用图必须无缺失或不支持的递归；技能变体/动作节点、怪物类型与身份、掉落职业/套装资格分别校验。大内容库按类型分块，不单文档无限膨胀。

环境指针H(environment,profileId)仅记录activeReleaseId和版本；测试账号授权不由客户端test=true决定。激活是一个可审计的指针切换，不修改旧release内容；旧发布记录和原摘要保留。

## 3. 发布流程（待执行）

1. 从待审配置源构建候选release，校验schema/字段、职业槽位、合法装等/品质/绑定、内容引用、数值溢出及已确认硬规则。
2. 对所有可达奖励计算最坏数量、字段字节、跨级邮件、交易/间接击杀读写预算；测试用例覆盖同源重试和回滚。不满足预算拒绝发布，不能先上线再漏奖。
3. 生成公开/私有清单及摘要，验证公开产物没有私有权重或凭证；记录代码/协议/资源兼容矩阵。
4. 在隔离测试环境校验接口和数据迁移，再完成eng-review所列发布前证据。当前没有目标环境，不执行此步骤。
5. 经发布范围明确后原子切换环境指针，返回发布审计结果；多实例缓存按releaseId加载不可变内容，不仅缓存latest。
6. 观察错误、配置拒绝、事务超限、未知结果与奖励守恒；异常时按第5节回退，不用重新随机奖励修复。

发布者与游戏普通玩家权限分离；自动发布工具不可获得任意玩家资产编辑入口。是否单独灰度账号、比例与观察时长属于发布方案参数，当前不虚构数值。

## 4. 生效矩阵（挑战/报价/既有奖励规则已确认，其余待收敛）

| 内容 | 建议生效点 | 已存在对象如何处理 |
| --- | --- | --- |
| 副本/怪物/奖励/掉落策略 | 新挑战创建时绑定当前合法版本 | 本局保留引用；已生成奖励永不重抽。新挑战采用激活的最新合法配置，当前挑战保留入场版本，已获用户确认 |
| 装备/词条模板 | 实例产生时固定引用与已滚属性 | 不热改历史随机值；模板修正需影响分析和明确迁移，不默认追溯削/加属性 |
| 服务价格/个人金库解锁价 | 新报价绑定配置及目标版本 | 旧报价若已失效拒绝并重新展示，不静默按更贵价扣款 |
| 成长/技能等级规则 | 明确的角色/挑战兼容发布方案 | 禁止仅切latest导致旧挑战技能/HP或等级邮件来源被重算发第二份 |
| 公开UI/动画资源 | 与客户端构建兼容时更新 | 未兼容资源不触发资产操作；资源失败重试不重复开局 |
| 体力刷新与已定容量规则 | 只能随获确认的规则变更发布 | 本局体力快照、既有解锁进度不被配置刷新覆盖 |

热更新可以改变未来选择，不得复用相同版本号改其含义。对于新旧公式跨挑战的属性变化，保留来源及修订记录，不能凭缓存强行合并。

## 5. 三类回退

- **配置回退**：激活指针指向仍与代码/协议兼容的旧版本；已有挑战用它绑定的配置继续解释，不删除新版本已生成对象，不撤已发物品。
- **代码回退**：先验证旧代码能读已写schema和协议；不能读则停止相关写意图、查询原结果、使用兼容构建或前向修复。回退不是把数据库也随意回滚。
- **数据恢复**：独立恢复计划，保留恢复点后合法操作的来源与账本；不能用一次数据库回档抹掉合法交易却让客户端继续重放。正式RPO/RTO、备份保留和重放方式待E07明确。

发布失败不能将RESULT_UNKNOWN当失败后重发补偿资产。回退后仍应查询旧operation/grant；如需业务补偿，另有明确授权、来源键和可审计计划，不直接手改余额。

## 6. schema迁移步骤与证明

每个迁移版本需包含sourceSchema、targetSchema、适用对象过滤、前置检查、转换定义、批量/字节预算、断点游标、幂等键、前后不变量、校验报告和回退/前向修复方案。字段名更改需契约兼容，不仅把schemaVersion加1。

| 迁移对象 | 转换要求 | 不得发生 |
| --- | --- | --- |
| 旧10格背包 | 容量升级20且保留原槽/实例/绑定，已有新版stage不降级 | 每次读旧数据重复送礼包或复制物品 |
| 个人/账号库 | 独立确定容器键；新个人20格，账号100全开 | 把原账号库物品自动搬成某角色个人库、重复初始化共享资产 |
| 装备Binding/Location/耐久 | 可验证来源和唯一位置；新耐久初始化依据已确认迁移政策 | 无证据猜绑定，耐久缺省一律0让玩家不能进本，存取洗强化/词条 |
| 新手与等级邮件 | 先查历史已发来源；缺旧来源证据时列人工决策项 | 直接把所有老角色当新号重发；或默认为已领而吞奖励 |
| 体力旧角色余额/挑战 | 按旧room支付记录可核对地构造快照/结算；不兼容活跃挑战先设计安全结束路径 | 默认删挑战、返还费用、跨窗口重扣、重复结算覆盖新本 |
| 邮件/待领 | 分开生命周期，保留原生成时间/归属/已领取来源 | 给永久待领加30天TTL或重抽词条 |
| 操作/来源/流水 | 保留原ID摘要/结果可查询，转换不改变重放含义 | 清operations后允许旧请求重新执行 |

迁移运行需以事务/版本更新与游戏写竞争，或明确维护窗口冻结受影响写并等待在途结果确认；不得一边无版本批改，一边让在线资产写覆盖。扫描只选候选，每个对象重读schema/version，已迁移项跳过，报告失败不掩盖。

活跃旧挑战是否兼容迁移不能只看字段是否齐全，还要核对代码/配置/截止/场景语义。无法恢复时先提交处理提案，用户未授权清档，不直接结束全部玩家挑战或抹掉资产。

## 7. 保留、归档与物品来源

邮件正文到期可清理，但来源/交付/过期凭据不能同时删掉导致节点重发；永久待领保留至交付，没有因数量硬限拒奖策略。地面场景关闭先逻辑失效，后台物理清理不改变已得收益。

operations、来源和账本在完整归档策略通过前不自动TTL。归档后如何防旧请求重放必须给出可查询的终止凭据或协议期限与拒绝机制，不能只压缩后假设没人重试。堆叠来源摘要不能无界增长，建议将详情保存在有界追加账本并以稳定来源/拆并记录追踪；具体物理映射和查询成本仍需E03联调。

## 8. 验收与未决

验收覆盖非法配置不能激活、正在挑战切版本不重抽、报价失效、缓存旧指针、旧代码读新schema、迁移中断重跑、并发转移、回城旧结算迟到、来源归档后重放。证据分别记录fixture、内存故障和真实环境结果，不能以文档检查通过替代迁移演练。

挑战配置动态生效点已确认；待收敛：成长/历史模板更新政策、旧数据无证据的补发/耐久初值、归档期限与RPO/RTO、目标环境能力。本文形成E06提案，不表示这些决定全部完成；完整方案与eng-review门禁不变。
