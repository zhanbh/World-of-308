# 事务、时间与恢复协议 v1

2026-10-20：S01–S04状态与事务补充见[核心契约v2](core-contract-v2.md)。体力按入场快照逐房扣至0，回城加载最新固定窗口；不沿用旧“每房刷新并检查足额”的事务模型。以下通用栅栏/去重/截止规则继续适用，未实现新迁移。

## 1. 命令执行模板

1. 平台适配器验证可信身份，校验白名单参数/大小/限流。读取不可变配置，生成本次候选奖励/ID；不在事务回调里调用平台外部服务。
2. 开启事务，以确定ID读取账号、会话和operations；先校验调用身份归属及当前sessionEpoch。旧会话不能因命中历史成功记录获得新的写入权限。
3. 同ID同摘要已提交则只返回原结果；异摘要拒绝。不检查旧expected版本后再拒绝一次合法重放。
4. 对新意图读取已知对象，重新取服务端now；先落实到期结果，再检查版本、房间、deathIndex、容量等。截止条件为now >= deadline；不存在客户端时间回溯。每次事务冲突重试都重新取now，排队中的旧请求不能永远获得入队时权限。
5. 计算业务变化，更新共同账号writeRevision及所有相关文档，追加有界流水和operations结果；一并提交。响应提交后返回。若到期转移同时拒绝本命令，仍须提交该到期状态，不能抛异常把它一起回滚。
6. 提交响应丢失返回未知；查operations决定是否已提交。数据库瞬态冲突可有界重试，不能将超时一概映射成业务拒绝。时刻边界以一次成功事务的服务端判定时间/顺序为准，不声称能重放物理断网或击杀的绝对时刻。

随机候选在一次应用调用的数据库自动重试间保持不变。另一调用同业务来源可能产生另一候选，但事务必须先查已存在来源记录，只有首个成功提交的候选生效；失败候选永不展示为真实奖励。所有随机范围来自绑定配置，客户端不能指定种子/结果。随机源及密钥只在服务端。

## 2. 每笔事务的读写集合

下表均隐含accounts栅栏、会话校验及operations；lease心跳不用operations但仍写栅栏。读操作与写操作都纳入预算。

| 业务 | 一致提交的对象 | 核心不变量 |
| --- | --- | --- |
| 首次登录 | identityLink、account、wallet、session、open结果 | 同身份只建一个账号；外部校验在事务外 |
| 会话接管 | account、旧/新session、旧challenge场景状态、open结果 | 旧写要么先提交，要么冲突后失效；未完成挑战失败，已完成不改结果 |
| 创建角色 | account职业占位、character、backpack、结果/流水 | 无半创建或重复职业 |
| 创建挑战 | account.active指针、challenge、结果 | 未关闭looting场景先拒绝，不静默丢弃地面物 |
| 进入房间 | challenge体力快照、room、结果/流水 | 实际或零扣费与manifest共同持久化；余量不足扣至0，允许合法推进 |
| 普通击杀事件批次 | challenge、当前room、character、wallet、结果/流水 | 来源唯一；经验/金币即时；材料装备留地 |
| 死亡事件 | challenge、room游标、结果 | deathIndex推进并记截止，不能因重复报告延长窗口 |
| 手动复活 | challenge、backpack纹章槽、结果/流水 | 资格/扣纹章/次数/生死一起改变；清职业CD，药品/饰品CD保留（旧核心待迁移） |
| 首领终局 | challenge、当前room账目、character、wallet、backpack、equipment或rewardGrant、结果/流水 | 首领与剩余小怪收益、通关收益及免费复活一起可见 |
| 地面拾取 | challenge、room.drop、backpack、equipment(若装备)、结果/流水 | 转移一次，满包不消失；橙装成功交付才绑定 |
| 待领领取 | rewardGrant、backpack、equipment、结果/流水 | 同原角色，pending变delivered及入包一起 |
| 穿戴交换 | character、backpack、涉及equipment、结果/流水 | 城镇、合法槽位、绑定与旧装备返包一起 |
| 放弃/结束/超时 | challenge、account指针、结果(命令触发时) | 逻辑关闭scene即可使全部未拾取物失效，无需逐条写每个drop |

首领房间账目一次写入全部尚未结算小怪的间接击杀及地面奖励计划；经验累加、金币自动入钱包，材料/装备保持正常地面拾取，不把全部掉落自动塞进包或待领。通关专属装备单独交付。升级用最新总经验计算，怪物入口等级不变；dead只有通关复活才清除。

单笔文档/操作预算必须在配置发布时校验并在入口再检查。首版房间账目与有限容器保证事务集合有界；若预算超限则禁用该配置，不能在战斗中临时把本该原子的一笔拆成多笔。来源流水按资产类别/受影响对象汇总，击杀明细在room，不为每个小怪额外创建十余事务文档。

## 3. 竞态的确定结果

| 竞态 | 处理 |
| --- | --- |
| 两个设备登录/旧设备写 | 共同account写冲突，epoch后提交者有效；旧写若先有效提交保留收益，否则拒绝 |
| 两次进同房/跨刷新重试 | 查room已处理及业务来源，包含零扣费；固定刷新不注入挑战快照，不能重复收费 |
| 两次复活、不同operationId | 首个转换dead→alive且deathIndex匹配；另一NOT_DEAD或版本冲突，零额外消费 |
| 复活与死亡到期 | 每次尝试检查now，已到期不得消费；处理到期状态后回城 |
| 首领与到期 | 首个有效服务端事务决定；到期已成立先失败则不接受迟报首领，客户端旧simulationTick不能追溯改判 |
| 首领与付费复活 | 客户端先flush事件；通关先提交则免费复活、后续付费拒绝。付费先有效提交代表已实际复活，随后通关不再收费；本协议不新增自动退还已消费纹章的规则 |
| 小怪直接击杀与首领间接击杀 | 同room账目并发冲突，spawnId只允许一个已结算来源，最终收益一次 |
| 拾取与场景退出 | 同challenge/account冲突；先拾取则入包保留，先关闭则拒绝拾取 |
| 通关与断线/接管 | completed永不转failed，关闭looting；已提交奖励不撤回 |
| 同一道具领取与穿戴/其他入包 | 共享容器/账号栅栏串行，容量和位置重新检查 |

首领死亡事件后本房间战斗结束，客户端停止残留伤害等危险效果进入安全拾取；不再接受新的战斗事件以产出额外收益。该阶段的持续在线心跳没有“通关后最大拾取时长”。

## 4. 权威时钟和修复

10秒死亡截止、10秒恢复/租约与2秒保护使用不同字段。保护期的模拟表现由客户端执行；服务端保留复活来源和参数，不据此声称已验证所有受击。冷却与DOT按战斗模拟时钟，死亡继续、断线/后台暂停；截止按墙钟继续。

后台通知、心跳和恢复按递增controlSeq/heartbeatSeq处理，不能重放旧报文延期；显式recovery只能resume解除。静默租约的检测误差见[接口契约](api-contract.md#5-心跳后台与恢复)。客户端优先用serverTime校正展示，不修改权威deadline。

业务请求/状态查询均懒检查截止；可另加批量扫描修复任务。扫描只找候选，真正终结必须事务内重读epoch、lease和result，防止扫到旧租约后误杀刚重连玩家。后台任务不依赖精确每10秒唤醒来保证安全：任何过期写请求都必须先被截止校验拦住。

新进程不恢复挑战；session.open即使发现旧lease未过期，也关闭旧场景并回城。通关后新进程只恢复资产/成功记录，不恢复地面物。正常进程内短暂恢复只查询可观测状态，不从服务端重建完整战场；场景内存丢失则结束场景。

## 5. 测试计划与环境出口

纯领域/事务适配器使用可控Clock和Random，测试结果检查权威账目及不变量，不只看响应成功。

| 测试组 | 必须覆盖 |
| --- | --- |
| 会话 | 并发首次登录、接管与资产写交错、open响应丢失、旧open重试不能抢回 |
| 房间/体力 | 不足、重复业务键、同请求异参、刷新边界、两个不同房间乱序 |
| 生死 | 普通怪残留击杀升级仍dead、首领残留通关免费复活、无纹章、上限、deathIndex过期 |
| 奖励 | 首领/小怪并发、重试随机固定、满包通关待领、地面满包不丢、绑定正确 |
| 时间 | deadline-1/deadline/deadline+1、事务重试跨截止、死亡4秒后断线6秒、重复suspend/heartbeat不延期 |
| 场景 | 无限在线拾取、迟到心跳不能续命、completed退出不失败、新进程不续关 |
| 原子性 | 每个写点故障注入、提交后丢响应、两个不同ID争同物，所有资产守恒且无半写 |
| 客户端 | 单写队列、事件缺号/重放、先flush再复活、升级不解除dead、离线暂停、不清合法死亡残留 |

内存适配器必须模拟冲突/回滚，不能靠单线程测试自证真实数据库原子性。CloudBase集成须另外证明：确定ID并发创建冲突、共同账号写冲突、事务读取/写入上限、按doc访问、索引查询、客户端无权直写、真实身份与函数调用授权、冷启动及故障恢复。若SDK行为与本设计假设不符，先修适配器或模型，再做上线链路。

测试环境数据必须标识可清理范围；禁止用现有414工程的数据或运行实例做实验。本轮仅形成规格，尚无上述测试已通过的声明。
