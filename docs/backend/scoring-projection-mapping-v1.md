# 当前穿戴评分的物理映射候选 v1

日期：2026-10-21。仅工程设计收敛，非正式eng-review；未修改代码、建索引或运行平台测试。依据[排行方案](leaderboard-loading-v1.md)、[资产映射](asset-physical-mapping-v1.md)。

## 1. 本轮选择

选择固定13槽同步维护个人评分事实与rankingEntries/characterId，不采用异步评分任务。character保存equipmentVersion、score、scoreReachedAt、scoreConfigRef；rankingEntry保存同一事实的公开字段与projectionVersion。角色及投影同事务提交，投影不是第二份可改资产；缓存只在查询时懒加载，不同事务更新全榜或全服名次。

不在此发明评分公式或决定破损是否扣评分：以评分配置的依赖声明为准。耐久导致的战斗属性失效仍遵守既定玩法，评分是否使用这种有效属性必须明确在公式配置中。依赖未声明或配置无法解释时，不允许默默保留旧分数并宣称新评分有效。

## 2. 读取完整实例，优先明确正确性

首版评分计算读取角色13槽中实际存在的全部实例，最多13件；不使用背包sortHeader或客户端总属性，也不将临时buff/背包/金库纳入评分。穿脱时包含操作涉及的新旧实例，按itemId求并集去重；每个实例验证归属、穿戴引用及版本，禁止仅凭槽位ID信任任意装备。

记B为原业务路径已经读取的实例集合，S为此次评分需要的实例集合，额外读取数为|S减B|，再加rankingEntry一个键；角色本来已经读取时不重复计。额外写入为rankingEntry一个键，若原命令不写角色则另加角色写。新建投影也读取确定键不存在性。Kread=|S减B|+1，通常Kwrite=1；存在角色额外写时Kwrite=2。这些是投影附加预算，不是完整事务预算。

| 场景 | 评分处理 |
| --- | --- |
| 创角初始武器穿戴 | 同笔创建初始评分与投影，不能等首次打开排行榜才记录达到时间 |
| 穿脱/替换装备 | 按提交后13槽重算，强化/套装变化只按评分配置应用一次 |
| 强化穿戴武器/耳环，含损毁 | 以最终成功/保级/降级/损毁状态计算，失败保持同分时不刷新达到时间 |
| 强化背包装备 | 不影响当前评分，无需重算穿戴；不误把目标强化值写入榜单 |
| 穿戴耐久/修理 | 评分配置依赖耐久或属性有效性时重算；无此依赖则无需评分投影读写 |
| 拾取、银行、背包整理、邮件领取 | 当前穿戴不变，不产生评分写；物品到包不等于自动装备 |

若清房/死亡磨损触发重算，E≤7的磨损实例通常已读，但评分还可能需要其他6槽实例及rankingEntry。应将实际集合并入终局/输入片段预算，不能只加一个投影写就认为成本完整。若该上界不满足目标平台预算，需完整提出替代映射，不在上线时异步漏更新。

## 3. 版本、时间与查询

分数改变时scoreReachedAt取成功提交所采用的服务端业务时刻，回调重试重新取得时刻；同分保持原时间，500→600→500重新记时。客户端操作时间、动画结束时间和缓存刷新时间都不能替代。原操作重放不更新任何评分时间。

equipmentVersion在影响穿戴评分输入的已提交修订中递增；projectionVersion与其对齐，评分配置版本另存。并发穿脱/强化/修理通过共享角色和账号栅栏冲突，不能用“最后收到的响应”覆盖投影。读取出现版本不一致时不把缓存反写角色；拒绝宣称最新并安排受控重建，重建不能凭当前装备猜测已经遗失的实际达到时间。

榜单查询按score DESC、scoreReachedAt ASC、characterId ASC稳定排序，并按评分配置版本隔离。首版不创建每次翻页的永久快照；游标绑定scope、scoreConfigRef及排序三元组，页间允许受并发装备变化影响而有重复/遗漏，客户端按characterId去重并支持重新刷新。不能把asOf标记称为整次翻页快照。精确本人名次及缓存参数仍须补查询/费用方案，不能使用全表扫描作为隐式默认。

## 4. 验收边界

实现后验证13槽最大装配、穿脱与强化/修理并发、500→600→500、同分换装、损毁、背包强化不影响排行、缓存失败不回滚装备、投影版本冲突及新旧公式隔离。当前只确定物理映射与预算规则，评分公式依赖、最大编码与真实SDK事务仍待核对，不宣称已通过。
