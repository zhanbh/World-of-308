# 配置、运营边界与验收基线 v1

2026-10-21。设计评审候选，无发布/迁移/运维操作。承接[配置方案](configuration-and-migration-v1.md)、[保留](retention-and-replay-proposal-v1.md)。

## 本阶段版本选择

一个release绑定职业成长/技能、战斗公式、动作/取消图、地图/怪物/行为、装备/套装、掉落/收集、XP/金币、价格/强化、评分及公开资源摘要。挑战创建时固定整个release；场内升级读取同release成长/技能，礼包来源仍按角色+等级节点唯一，不含release。首版禁止进行中的挑战热换成长/技能公式；新release只对新挑战生效。旧挑战解释依赖在终止后仍随来源/操作保留。

城镇服务新报价绑定当前价格及实例/容器版本；过期报价拒绝刷新。既有装备保存生成模板与随机值，普通配置升级不改历史实例；修复历史装备需要独立迁移方案。评分公式独立版本隔离，不混入同榜；跨公式达到时间不伪称玩家历史时刻，新榜启用时明确版本切换时刻，实际政策随首版评审确认。

输入/资源codeCompatibility不匹配时开局前明确阻止加载，不创建收费房间；旧挑战无法解释时停止接受新战斗片段、保留已提交资产及原结果，走受控兼容修复，不以随机新配置续打。

## 评审候选与发布冻结不同

已有公式/数值提案、v25～v46结果提供初始调优依据；当前不再扩展伤害/AI试算。正式第一份可运行release的每行数值和资源引用须在实现配置任务中导出完整表、schema校验与算例，不能直接把文档中“候选”字段当默认生产常量。没有合法表就CONFIG_NOT_READY，不用全蓝装备/测试补缺代替正式策略。

工程评审检查字段、边界、初值来源与调整路径；发布验收检查实际表、操作/字节、完整成长经济和真机，不要求文档阶段已拥有全部真机数字，也不把未完成调参包装成最终完成。

## 运维与数据恢复

首版保留全部权威O/J/来源终态、配置与被引用依赖，不启自动TTL/冷热搬迁。调试日志与凭证完全分离，日志按最小可定位字段输出；敏感身份仅授权Adapter使用，普通日志用内部引用。备份应覆盖资产与凭据的一致恢复点；整笔已确认提交丢失不能靠客户端重放猜复原。

发布前必须给出所选环境的真实备份周期、覆盖范围、保留与恢复能力，再用独立测试资产演练恢复、栅栏提升及引用闭包。没有真实环境、并发量和账单目标时不预签RPO/RTO或金额；默认不开正式写入口，先完成隔离验证。清档、自动补发、币兑换比例和付费规则变更都不由本稿授权。

## 验证责任与失败处置

| 验证层 | 主要证据 | 失败后的状态 |
| --- | --- | --- |
| 共享纯规则 | 精确算术/舍入、同输入不同切片、动作中断/残留/边界、随机游标与版本编码 | 修正规则或编码合同并补复核，不进入在线资产联调 |
| 内存事务故障 | 每写点注入失败、原操作未知、接管/复活/通关/磨损/发奖竞争 | 修正原子编排，不以补偿脚本替代原规则 |
| SDK隔离环境 | 精确版本/身份、确定doc事务、最大编码/调用、冲突回调、索引count、备份恢复 | 阻断该适配或正式发布，重新评审映射/SDK，无自动弱校验降级 |
| Cocos与微信真机 | Loading/切房/恢复、控制与地图、UI触控/资源异常、Note20 Ultra长时峰值 | UI/表现/分配优化，逻辑合法效果和收益不得丢弃 |
| 内容经济 | 战士1～30有效时间、三本/所有难度、真实掉落换装、药品/修理/材料与纹章净额 | 改候选配置后重测；已确认概率/体力/绑定等规则需新决定才能改 |

测试与发布证据均未执行。本阶段的出口是可评审的候选合同与已知限制，不是正式运营已就绪。
