## 2. 运行时与环境选择

仓库本地后端测试要求Node≥24，不代表目标云函数已支持同一运行时。本轮不选择未核实版本。落地前记录：目标环境ID/区域、小游戏AppID关联方式、云函数runtime、Node/TypeScript构建目标、精确SDK版本及锁文件、数据库产品与事务/索引能力。

研发/内测/正式数据、授权配置与资源隔离，不与旧棋牌项目共用钱包、身份映射或数据库实例。正式配置不能通过普通玩家请求开test profile。环境创建/费用/部署操作需之后明确目标范围，当前无实际连接参数或密钥。

## 3. 可信身份与会话

推荐仅保留一种经过验证的平台调用链作为首版游戏入口，Adapter每次取得与本次调用绑定的可信platform/appId/subject，再解析内部账号；不能接受event.openid、请求体accountId、客户端sessionId单独作为身份。具体可信来源使用平台上下文还是登录code服务端交换，待小游戏官方接入核验后定。

禁止在复用实例的全局变量保存用户身份、请求参数或可变账号状态；可缓存不可变配置与无用户态SDK连接。调用来源必须可识别，HTTP、定时任务、控制台/内部调用不能共享一套默认“取到OPENID就信”的路径。

平台凭证、session_key、管理员密钥等不得写入仓库、公开配置、前端包、operation结果或日志；采用目标平台支持的服务端秘密注入方式，实际能力待核验。session.open的launch来源/epoch与角色归属沿契约；同账号写共同栅栏，旧会话不能因命中历史结果再获写权。

## 4. 数据权限与管理操作

权威集合默认拒绝普通客户端直接读写，通过授权命令/裁剪视图访问。公开配置可独立只读发布，私有权重、流水、操作结果、钱包、容器及挑战不公开。安全规则和云函数调用权限都需目标环境负面测试，不能仅看控制台选了“私有”。

服务端每请求验证账号、角色、物品/容器归属及场景/会话；管理员SDK能力不是业务许可。运维/发布/迁移角色与游戏玩家身份分开，最小权限范围要在目标环境确认；不暴露通用任意增币、补发、改schema的玩家接口。

如需要客服补偿或人工修复，必须另行设计受控审批/来源键/审计/可追溯回执；本轮不新建管理后台，也不默许手改生产钱包。

## 5. 威胁模型与两项关键缺口

| 威胁 | 必需校验 | 仍有限制 |
| --- | --- | --- |
| 请求重放/参数伪造 | operation摘要、版本、来源、白名单、数量上界 | 原请求结果未知不能另开新扣费 |
| 旧会话/跨角色取物 | 当前epoch+账号写栅栏、容器/物品绑定归属 | 不依赖ID不可猜或UI隐藏按钮 |
| 客户端假击杀/超速 | manifest、事件顺序、截止、收益预算/配置快照 | 当前不能证明本地物理战斗真实，内存测试不证明反作弊 |
| 假NPC位置/服务许可 | 签发上下文与角色location/epoch一致、服务种类/目标验证 | 城镇移动客户端运行，上下文本身不能证明玩家真走到银行 |
| 假药品CD/HP或饰品状态 | 权威消费来源、动作序号、模拟游标、资源/CD/装备限制 | 当前协议缺完整可验证状态，不可直接信clientHp/ready |
| 高并发/大包/批量滥用 | 身份/账号/命令级限流、包长/条数/扫描/事务预算 | 具体阈值须测量与失败策略，不臆造平台默认 |

### 待决A：服务地点证明

可选方案需比较：仅城镇合法锚点/服务上下文做内测行为约束；或增加服务端城镇路径/步长与状态转换校验。前者不能证明真实步行，后者增加同步、速度验证和恢复成本；不得直接把内测弱校验宣称可正式运行。用户服务地点规则不变，选择何种证明强度在eng-review前补方案及风险接受，不在本稿暗中放宽到处开银行。

### 待决B：药品/饰品动作校验

需明确服务端可判定的模拟tick、HP/MP/最大值和动作CD事实，保持死亡继续、断线暂停以及复活/回城重置矩阵；不能为便于服务器计时改成与玩法冲突的墙钟CD。候选“有序动作日志＋服务端有限重算”应与成本/精度比较；若仍依赖客户端镜像，必须标出可伪造范围及内测限制。正式经济开放前不能用“资产服务端权威”掩盖动作真实性缺口。

用户已确认首版不做实时多人战斗；解决上述验证不等于自动引入常驻实时服务器。具体方案需专题设计，不以技术取舍重开已定玩法。

## 6. 限流、错误与日志

限制维度候选：身份入口、账号命令、事件批大小、查询页/扫描量、同账号在途写、服务报价/领取重试和后台任务；已提交未知结果的查询需有恢复通道，不能一限流就逼客户端换ID。批量和超限配置在发布前拒绝，不在战斗中漏奖。

结构化日志包含requestId、脱敏account/character、operation/source/challenge、配置/协议/schema版本、时延、拒绝/未知/冲突与预算；不含秘密、完整私有物品库或原始身份payload。日志采样不得删权威账本/operations。

监控需覆盖：错误/未知结果比例、事务冲突和重试、预算超限、领取失败与来源异常、会话拒绝、投影积压、配置加载失败、端到端时延与资源加载。阈值、成本预算、告警接收人及响应时间待环境/运营设计明确，当前不创建监控或发送通知。

## 7. 发布、备份与恢复

代码、配置、schema、索引/权限分别有版本和兼容矩阵，部署前完成迁移演练、权限负测与真实事务预算证据。发布不自动继承旧项目钩子；不能在包里嵌服务端凭证。

备份方案需确定范围（账号/钱包/物品/来源/结果/配置及必要身份映射）、一致性恢复点、隔离恢复环境、RPO/RTO与保留时间。平台是否提供所需备份/回档、价目和地域能力本轮未核实，不在文档承诺“自动可恢复”。

恢复演练必须验证：同一物品位置不重复、钱包/账本和来源一致、旧会话失效、旧请求不可重复消费、永久待领不丢、恢复点之后合法操作如何处理。不能只导入装备表而遗失operation/grant，或回档余额后允许已执行请求重放。
