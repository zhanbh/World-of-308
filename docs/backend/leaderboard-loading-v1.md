# 排行榜懒加载与评分时间方案 v1

更新：2026-10-20。状态：工程提案，未实现、未评审通过。依据：[规格](../spec.md)、[数据字典](data-dictionary-v2.md)、[访问路径Q12](access-and-transactions-v2.md)。

## 已确认行为

排行榜不实时推送，按玩家查看时懒加载，关闭后不轮询。总榜与战士/猎人职业榜按当前穿戴评分，不计背包、金库、角色基础属性或临时buff，无排名奖励。

同分按最近一次达到当前分数的实际时间排序：500→600→500时返回500重新计时；换装但评分仍500则保留。不能以打开榜单、缓存生成或后台任务处理时间替代实际达到时间。

## 工程方案建议

### 1. 将个人评分事实与榜单查询分开

影响当前评分的装备变化事务，按固定13槽与绑定评分配置计算个人评分；若分数改变，保存新score及该次权威事务时刻作为scoreReachedAt，分数未变仅推进必要装备版本。这里维护的是单角色评分事实，不计算其全服名次，不向其他玩家广播。

这样不需要无限保存每次换装日志来在首次看榜时回算达到时间。若改为延迟计算个人评分，就必须保留足够的中间装备/评分变化事实，不能跳过600直接把两次500误判为分数未变。首版建议选择前述固定13槽即时事实方案，是否采纳仍待工程评审。

### 2. 打开时按索引取榜，复用有界缓存

打开榜单后服务端校验当前会话，按scope/职业、评分配置版本、游标与页大小查缓存；有效缓存可返回。无缓存或超过已配置时效时，通过score DESC、scoreReachedAt ASC、characterId ASC的索引读取有界页并填缓存，不每次扫描所有角色重排。

缓存属于投影，不能作为装备/钱包真相源。返回asOf、评分配置版本和缓存/投影新鲜度；不承诺“当前每毫秒准确排名”。缓存时效数值待性能/成本设计，不在本稿自定秒数。玩家自己的最新评分可与榜单快照不同，界面应标出更新时间，不把快照外的新分数插入旧榜并声称准确名次。

并发刷新同缓存键可合并工作，短暂失败保留可标注的旧快照或返回明确失败；不能以空列表冒充加载成功。具体刷新锁/过期恢复与缓存存储介质在适配设计明确，不因懒加载新增长期常驻服务。

### 3. 排名投影与事务一致性

2026-10-21当前候选选择已细化为[评分物理映射](scoring-projection-mapping-v1.md)：固定13槽同步计算，character事实与rankingEntry同笔提交，不启用异步评分队列。原文“建议”不表示两套实现并行；公式依赖、查询参数与平台预算仍待关闭。

建议角色评分事实与对应rankingEntry同原装备变化事务提交，避免另建必须可靠投递的异步评分队列；E03需据真实预算验证附加读写与13槽计算成本。缓存无需同事务更新，允许它在时效内非实时；不会因为缓存更新失败回滚玩家装备操作。

若后续规模/预算迫使rankingEntry异步，须保存每次分数实际变化时刻及有序版本，持久投递、失败恢复和防旧覆盖；不能只用内存事件或最后一次equipmentVersion就丢失500→600→500的变化。此替代方案需重新评审，不同时把两套方案称为已采用。

评分公式/配置更新引起全量重算另行发布：先生成一致版本投影，再切换榜单版本；不得在同一榜单混算不同公式。旧缓存按评分配置版本隔离，重算政策与真实达到时间语义待数值/发布专题确认。

## 验收与未决

- 连续500→600→500保持正确新时间；500换装仍500保留时间。
- 请求榜单不修改scoreReachedAt、不触发全账号资产写、不返回私有库/钱包。
- 并发装备变化后旧回包/旧投影不覆盖新评分事实；缓存允许非实时但有asOf。
- 分页同分/同时间以ID稳定排序；跨刷新分页是否绑定同快照需在分页契约明示，不能承诺无快照时零重复/遗漏。
- 缓存失效、刷新丢响应、请求合并、旧公式缓存、更新失败与未上榜自查分别有明确结果。

待确定：评分公式、缓存时效/载体、分页快照、自身排名计算方式及平台索引/预算实测。榜单UI新增他人完整检视不在本方案默认授权，须先核对范围。完整方案收敛与eng-review门禁不变，本轮没有代码/缓存或云资源操作。
