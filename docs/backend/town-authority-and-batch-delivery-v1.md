# 城镇地点授权与有界批领合同 v1

2026-10-21。补齐E04服务授权与批量边界的工程候选，不增加远程银行/邮箱、金库整理或新增赠品。无业务实现/平台测试。

## 城镇坐标的权威来源

城镇无战斗效果，采用characters.townState内嵌小检查点（完整≤4KiB），不复用挑战按需分片CP。字段：mapRef、sceneEpoch/timelineEpoch、position整数、velocityRemainder、acceptedSeq/Tick、时间锚点、locationRevision。C04出旅店只初始化固定合法城镇锚点；新上线先隔离旅店、回城副本门口等既定落点仍按各事件入口，不统一传送到同一NPC。

城镇移动也只收有序输入，经共享移动/扫掠边界规则验证，最大片段1秒/32条、最多1秒预测、时间前沿不超服务端累计活动预算。只改C中的位置、游标和必要地点版本；A/S/O/C构成控制写路径，不强造资产J。正常空闲不持续写模拟，下一合法输入按原墙钟活动预算推进；不能把客户端自报position直接写成服务地点。

地图manifest必须包含旅店/各副本出口和NPC服务锚点及可达区域。候选服务交互半径24源像素；仅当前已确认位置与锚点距离平方≤24²且同场景时允许C05 open，不用渲染缩放后的屏幕距离。sceneEpoch、mapRef、anchorId、serviceKind由服务端互相匹配；传送只允许已注册场景转换，不能通过选择anchorId任意瞬移。

服务上下文记录account/character/sessionEpoch/sceneEpoch/locationRevision、anchorId、serviceKind、issuedAt/status。玩家移动或离开服务区域、关闭面板、进本、切角色/接管时使旧上下文失效；客户端移动意图先结束面板，不能靠仍显示旧面板继续消费。每个服务资产事务读取C及上下文，重验距离/地点版本/代次；A与C使它与移动/关闭竞争。读原operation仍允许返回历史已提交结果，不恢复旧上下文写权。

背包城镇扩容/穿脱/快捷位在允许城镇地点执行，不要求靠任意NPC；银行存取/个人扩容需银行上下文，邮件完整列表/领取需邮箱上下文。HUD只查提醒摘要，不借预取开放完整远程库存。商店/修理/强化按各自serviceKind授权。配置未提供合法锚点时CONFIG_NOT_READY，不默认全城都在服务范围。

场景/服务资源加载不创建资产消费；同页关闭与在途请求的结果由原事务顺序决定，拒绝新意图不撤销已提交旧意图。离线重进使用既有上线旅店规则，城镇检查点不变成跨设备续副本授权。

## 邮件一键领取的固定边界

一键领取是可部分成功的批处理，不是承诺把所有邮件放进一笔大事务。候选单批最多20个附件、扫描最多100封候选邮件；来源按既定倒序与稳定ID遍历，满包项跳过继续尝试后项，可堆叠附件只领可容纳部分。达到扫描/处理边界返回继续游标，不能宣称后面全部领完；新插入邮件留下一次刷新，不混入本次已固定候选列表。

deliveryBatches/H(accountId,batchOperationId)保存归属、原意图摘要、候选附件引用（≤20）、每项稳定childOperationId、各项已提交状态及继续游标，完整编码≤16KiB。准备候选扫描在事务外，批次建立时重验会话/邮箱上下文并固定引用；扫描不是资产授权。每项事务重读来源、实际余量/到期、B及必要实例，沿现有部分领取规则交付，同笔写child O/J、来源、容器及batch中该项结果。额外batch键读写计入该项预算；最多20项，batch不无限积累结果。

子操作ID由batch+附件序号确定，不由重试随机生成。成功丢响应先查批次及child O，已完成项不再执行；新ID只表示用户明确发起新的批次，来源余额仍防重复领取。邮件在执行前到期则该项明确过期，不按扫描时未到期承诺领取；未领过期部分不补发。未知提交不得标跳过，暂停该批次查询原结果后再继续。

一键执行可跨多个有界服务请求，每次候选最多执行4项；超时沿持久批次恢复，不依赖进程一直活着。用户关闭面板不撤销已提交子项；未执行项再次执行时仍须当前合法邮箱上下文，不拿旧批次绕过地点授权。批次完成或部分退出返回实领/未领/跳过摘要，永久待领用独立来源类型/列表，不与邮件过期规则混用。

新增batch只协调进度，不增加同附件的第二份可领余额。单个堆叠附件原R8+P/W5加batch一键为R9+P/W6；装备附件R10+P/W7。批次建立/继续自身只写控制结果与batch，不虚构资产J；子项资产事务保留完整O/J。具体SDK时间/操作/批次冲突在接入验收，不承诺4项必在某毫秒内完成。
