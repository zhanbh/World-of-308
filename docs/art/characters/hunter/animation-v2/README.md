# 猎人动画 v2 — 细腿与内外腿交替修订

日期：2026-10-18。状态：美术修订稿，未接入游戏。用户指出v1小人腿偏粗、跑动看起来始终同侧腿领先；原v1转为问题对照，不再按播放正常宣称步态通过。

## 本轮改动

- 待机/拉弓/跑姿小人及单箭普攻的腿部重绘为更细的轮廓，保持原头部、上身、服装识别点和腿长；已认可的高精立绘不修改。
- 跑动拆成近腿承重、远腿承重两个半循环，分别检查髋部连接、膝盖轨迹、脚踝与脚掌位置。前后腿在交叉处要有明确遮挡，不能只换腿带或标签。
- 普通文字提示多次仍返回相同侧跑姿，相关稿件保留为rejected/初稿；补充独立关节轨迹参考后继续重绘。轨迹图只作参考，不通过程序将原图肢体挪动或镜像。
- 预览加入v1/v2同帧切换，以及两版近/远腿接触位的腿部同尺度对照。

## 源稿与打包

近腿与远腿半循环为分别生成的2×2源图，选7张有效关键帧装入4×2图集（最后1格留空），不把错误远腿下沉帧加入播放；单箭普攻仍为8帧4×2布局并重绘腿部。跑动7×80ms=560ms，普攻720ms。统一格子416×416、脚底锚点(208,352)。近腿源组固定0.36、远腿源组固定0.338，匹配两份生成源稿的角色显示身高；不逐帧拉伸人物，也不压扁腿部。普攻源组固定0.48。具体帧来源、平移、公共落地线和尺度在animation.json记录，禁止将不同来源/错误帧悄悄混成“8张都正确”。

打包器仅裁格、按源组统一缩放/平移和编码GIF；不重画人物、不缩放某一条腿。若源文件列出source覆盖，表示该时位来自另一半循环源图。GIF导出与预览使用相同帧序/时间；时间仍是美术审阅用参数，不改正式攻速。

重建：

```sh
clang -fobjc-arc -fno-modules -framework Foundation -framework CoreGraphics -framework ImageIO client/tools/pack-hunter-animation.m -o /private/tmp/world308-hunter-pack
/private/tmp/world308-hunter-pack docs/art/characters/hunter/animation-v2/animation.json
```

## 审阅原则

这类缺陷必须看源帧轮廓和实际播放；自动检查8帧、文件存在、标签正确，只能验证播放管线，不能证明人体步态正确。每次接触位都沿髋→膝→踝→脚连续追踪，同一条腿在前半、后半周期应分别前撑和后摆。首版及未选用稿件保留用于回归对照，不把此前错误判断覆盖掉。
