# 猎人细腿与步态 v2 — 审阅记录

## 原问题与修订

播放清单并没有把同一帧重复8次；错误来自生成图与视觉验收：即使部分帧换了腿带位置，前方大腿到小腿的连续轮廓仍让人感觉同一侧腿一直领先。仅检查PNG数量、GIF循环或NEAR/FAR标签不能锁定这一缺陷。本轮采用原图/源帧同尺度对照，并逐腿沿髋—膝—踝—脚追踪；不把自动元数据检查当成人体动作测试。

小人比例稿和普攻已由imagegen收细大腿、膝、小腿，保留腿长、丝袜与短战靴。三版高精主立绘SHA256与修改前一致；高精服装参考也未重绘。

## 工程检查

- 图集1664×832、透明RGBA，单格416×416；跑动7帧，普攻8帧。
- GIF实际解码帧数7/8，正常/慢放时长匹配，disposal=2；跑动图集最后一格为空且不进入播放。
- 近腿源组固定0.36、远腿源组固定0.338，使两份不同生成源稿的显示身高接近；普攻0.48。没有逐帧拉伸身体或单独压扁腿。
- 预览内嵌元数据与animation.json一致；Node服务和页面脚本语法检查通过。
- 浏览器加载4份新旧图集，state.error=null；新旧同帧切换、接触位定位、0.25×/1.5×有效。旧版逐帧上限7，新版上限6，均从0计；不会播放新版空格。
- 三版主立绘哈希及输出元数据保存在assets.json。
